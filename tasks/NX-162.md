# NX-162 — Funnel Truth: checkout click/convert events + split bot-led/assisted

**Owner:** TBD · **Faza:** P1 · **Track:** Analytics / Revenue Intelligence (PARTEA D, Faza 0) · **Branch:** `feat/NX-162-funnel-truth` · **Complexitate:** S · **Estimare:** 3-4 zile

## Goal
Închide golurile de adevăr rămase în funnel-ul de venit, ca orice cifră de conversie/atribuire raportată să fie **fapt determinist**, nu estimare. Concret: instrumentează `checkout_link_clicked` + `checkout_link_converted` și separă atribuirea **bot-led vs assisted** în rollup — ca pasul `created → clicked → converted` și liniile de venit să fie reconstruibile din date reale.

## Business Context
Prima poveste care reînnoiește contracte e „sistemul se plătește singur?". Fără evenimentul de click și cel de conversie, funnel-ul are un gol la mijloc și venitul apare doar dintr-un join pe `orders` — nemăsurabil ca traiectorie. Split-ul bot-led/assisted e cifra pe care o citește cumpărătorul: bot-led = faptul dur, assisted = cifra moale. **Niciodată însumate** (dublă numărare).

> Reality-check (2026-07-10): Defect 1 (cost=0) e DEJA reparat via event `llm_usage` (`runner.py` + `aftercare.py`, NX-103/125). **NU e în scopul acestui card.**

## Technical Description
**(1) `checkout_link_clicked`** — nu e doar un `emit()`. Linkul de checkout trebuie să treacă printr-un **endpoint de redirect** pe serverul nostru care:
- primește `ref_code` din query (`GET /r/{ref_code}` sau similar),
- ștampilează `checkout_links.clicked_at = now()` (idempotent — primul click câștigă, nu suprascrie),
- emite evenimentul, apoi face `302` către `checkout_links.url` real.
`ctx` clasic nu există în afara pipeline-ului → evenimentul se scrie direct în `analytics_events` (insert append-only, tenant-scoped) cu `conversation_id`/`contact_id` derivate din `checkout_links`. Fără PII: doar `ref_code` + ids.

**(2) `checkout_link_converted`** — match-ul de comandă din [orders.py](src/webhook/orders.py) scrie deja `orders.attributed_checkout_link_id` + `checkout_links.converted_order_id`. Lipsește doar **emiterea evenimentului la momentul match-ului** (`ref_code`, `order_id`, `attribution`), în aceeași cale.

**(3) Split bot-led vs assisted în rollup** — `usage_daily` colapsează azi în o singură pereche `orders_attributed`/`revenue_attributed` ([usage.py:60-63](src/db/queries/usage.py#L60)). Adaugă coloane de split derivate din `orders.attribution` (`direct_bot` vs `assisted`), calculate în CTE-ul `ord` cu `FILTER (WHERE attribution = ...)`. Migrare care adaugă coloanele + update la `_ROLLUP_SQL` + upsert.

## Principii CLAUDE.md aplicabile
- **P7 (business_id pe tot):** endpoint-ul de redirect derivă tenantul din `checkout_links` (care are `business_id`); orice query nou are `WHERE business_id = $1`. Rollup-ul filtrează deja explicit.
- **P10 (observabilitate din runner):** evenimentele de funnel se scriu append-only în `analytics_events`, nu în calea de răspuns.
- **P12 (PII un singur loc):** `properties` conține DOAR `ref_code`/ids/counts — zero telefon/text. Redirect-ul nu loghează query-uri cu PII.
- **P2 (LLM la 2 puncte):** determinist total, zero LLM.

## Implementation Steps
1. Migrare: coloane split în `usage_daily` (`orders_direct_bot`, `revenue_direct_bot`, `orders_assisted`, `revenue_assisted`) — nume delta ordonat (`0NN_usage_split_attribution.sql`, runner `migrate.py`).
2. Endpoint redirect `GET /r/{ref_code}` (webhook app): lookup `checkout_links` → stamp `clicked_at` idempotent → emit `checkout_link_clicked` → `302` la url.
3. Emit `checkout_link_converted` în calea de match din [orders.py](src/webhook/orders.py) (la setarea `converted_order_id`).
4. Update `_ROLLUP_SQL` + upsert cu coloanele de split (FILTER pe `attribution`).
5. Teste: tenant-scoped, „no PII in event properties", idempotență click, split ≠ sumă.

## Test Cases
**Happy Path:** (a) click pe `ref_code` valid → `clicked_at` setat + event + `302`. (b) comandă matchuită pe `ref_code` → `converted` event + split corect în rollup.
**Edge Cases:** (a) dublu-click → `clicked_at` neschimbat (idempotent), un singur event „primul". (b) split: 3 direct_bot + 2 assisted → coloane 3/2, niciodată 5 într-o coloană „atribuit".
**Failure Cases:** (a) `ref_code` inexistent → `302` fallback safe / `404`, zero crash, zero leak. (b) rollup pe zi fără comenzi → coloane 0, nu NULL.
