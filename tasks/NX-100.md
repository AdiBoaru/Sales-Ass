# NX-100 — Demand Capture: îmbogățire evenimente + `unmet_query` (senzor de cerere)
**Owner:** S · **Faza:** P1 · **Zi/Ord:** track «Cerere & Produse», pasul 1 · **Branch:** `feat/NX-100-demand-capture` · **Complexitate:** M · **Estimare:** 3-4h

## Goal
Fundația raportului de business «Cerere & Produse» ([ANALYTICS-AUDIT-SI-BLUEPRINT.md](../docs/ANALYTICS-AUDIT-SI-BLUEPRINT.md) §4bis):
botul vorbește deja cu fiecare client, dar evenimentele emise spun prea puțin pentru a afla *ce
se vinde, ce se caută, ce se cere și ce NU s-a găsit*. Azi `product_search` emite doar contoare
([catalog_tools.py:174](../src/tools/catalog_tools.py)), `agent_recommended` doar `{n}`
([agent.py:474](../src/worker/stages/agent.py)), iar `cart_updated`/`checkout_link_created` doar
`{items, value}` ([commerce_tools.py:111](../src/tools/commerce_tools.py)) — fără `product_ids`,
fără atribute, și **fără niciun semnal pentru căutările cu zero rezultat**. Taskul îmbogățește
aceste evenimente (PII-safe) și introduce evenimentul nou `unmet_query`.

## Business Context
Date pe care Google Analytics / ads NU le dau: ce branduri/atribute cer clienții cu cuvintele lor
și ce au cerut și n-ai avut. Astea deblochează decizii de restock, extindere catalog, conținut
PDP și gamă de preț — diferențiatorul cu cea mai mare retenție. Fără captura din acest task,
secțiunile 1-3 ale raportului (NX-101) nu au sursă de date.

## Technical Description

### Regula PII (P12) — capturăm chei normalizate, NU text brut
`product_search` exclude azi **deliberat** `a.query`/`concerns` text fiindcă pot conține formulări
PII. Păstrăm regula: îmbogățim DOAR cu **referințe de catalog structurate** (chei normalizate,
id-uri de produs/brand, enum-uri de concern, bandă de preț) — niciodată mesajul brut.

### 1. `product_search` — adaugă atribute normalizate + id-uri rezultate
La emit-ul existent ([catalog_tools.py:174](../src/tools/catalog_tools.py)) adaugă:
```python
ctx.emit(
    "product_search",
    mode=mode, count=len(products), relaxed=relaxed,
    had_price_filter=a.price_max is not None,
    category=a.category,                 # cheia de categorie (din triaj/agent), nu text liber
    brand=a.brand,                       # valoarea de brand din arg (id/slug), nu propoziție
    concern_keys=concern_keys or [],     # enum-uri normalizate, deja calculate în funcție
    price_band=_band(a.price_max),       # ex. 'sub_50' / '50_150' / 'peste_150' (None→'orice')
    top_product_ids=[p["id"] for p in products[:6]],  # id-uri catalog (nu PII)
)
```
`_band()` = helper mic determinist (mapează `price_max` la o bandă). `concern_keys` sunt deja
normalizate în corpul funcției (sunt enum-uri din taxonomie, nu text de la user).

### 2. `unmet_query` — eveniment NOU pentru cerere neîmplinită
Sursa unică pentru tile-ul «cerere neîmplinită». Se emite când o căutare nu produce ofertă utilă:
```python
if not products:                          # zero rezultate chiar și după plasa SQL
    ctx.emit(
        "unmet_query",
        kind="no_result",
        category=a.category,
        brand=a.brand,                    # brand cerut dar inexistent = semnal de extindere catalog
        concern_keys=concern_keys or [],
        price_band=_band(a.price_max),
    )
```
Doar atribute normalizate (P12). `kind` permite extindere ulterioară (`low_result`,
`out_of_stock_only`) fără schimbare de schemă (jsonb properties).

### 3. `agent_recommended` — adaugă `product_ids`
La emit-urile din [agent.py:474,493](../src/worker/stages/agent.py) adaugă `product_ids=[...]`
din produsele efectiv puse în reply (din `ctx.retrieval` / lista afișată), păstrând `{n, rich}`.

### 4. `cart_updated` + `checkout_link_created` — adaugă `product_ids`
`checkout_link_created` ([commerce_tools.py:111](../src/tools/commerce_tools.py)) are deja `cart`
local → `product_ids=[c["product_id"] for c in cart]`. `cart_add` ([commerce_tools.py:170](../src/tools/commerce_tools.py))
are `product_id` în arg → adaugă-l la `cart_updated`.

### Câmpuri TurnContext / owner
Niciun câmp nou pe `TurnContext`. Toate sunt apeluri `ctx.emit(...)` (acumulează în `ctx.events`,
scrise append-only de processor prin `insert_events` — P10). Tool-urile rămân singurii emițători
ai propriilor evenimente.

## Principii CLAUDE.md aplicabile
- **P12 (PII într-un loc):** ZERO text brut de la user în properties — doar chei normalizate +
  id-uri de catalog. Telefon/PII rămân exclusiv în `channel_identities`.
- **P10 (observabilitate din runner):** evenimentele se acumulează în `ctx.events`; processor-ul
  le persistă — tool-ul nu știe că e măsurat dincolo de `emit`.
- **P7 (business_id pe tot):** evenimentele sunt scrise tenant-scoped de `insert_events`.
- **P2 (LLM doar triaj+agent):** ZERO LLM nou — `_band` și extragerea de id-uri sunt cod determinist.

## Test Cases
**Happy Path:**
1. Căutare cu rezultate → `product_search` cu `top_product_ids` populat, `unmet_query` absent.
2. `checkout_link` pe coș de 2 produse → `checkout_link_created.product_ids` are 2 id-uri.

**Edge Cases:**
1. Căutare brand inexistent, 0 rezultate → `unmet_query {kind:'no_result', brand:...}`; `product_search.count=0`.
2. `price_max=None` → `price_band='orice'`; fără filtru de preț.
3. Recomandare fără produse (răspuns pur text) → `agent_recommended.product_ids=[]`.

**Failure Cases:**
1. `concern_keys` gol → `[]`, nu NULL; eveniment valid.
2. Emit pe ramura de fallback SQL → câmpurile prezente identic (mod `sql_only`).
