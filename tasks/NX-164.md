# NX-164 — Demand Queries: read-side agregat peste faptele de cerere (drilldown)

**Owner:** TBD · **Faza:** P1 · **Track:** Analytics / Revenue Intelligence (PARTEA D, Faza 1→3) · **Branch:** `feat/NX-164-demand-queries` · **Complexitate:** M · **Estimare:** 1.5-2 săpt

## Goal
Stratul de citire care transformă faptele capturate în NX-163 în răspunsuri de business: top zero-result, cerere out-of-stock, variante lipsă, top branduri/produse cerute — fiecare rând **drilldown-abil prin `conversation_id`/`turn_id`** la dovada reală. Modul de query determinist; **fără `estimated_value` stocat** — oportunitatea se derivă la citire.

## Business Context
Astea sunt datele pe care comerciantul le deschide și ia decizii de stoc/catalog/preț din ele. Valoarea stă în **fapte numărate + dovadă**, nu în estimări: „73 cereri · 0 în catalog" (el înmulțește cu marja lui), nu „ai pierdut 13.140 RON" (moare la prima întrebare „de unde știi?"). Fiecare rând duce la conversațiile reale din spate — asta e credibilitatea care reînnoiește contracte.

## Technical Description
Modul de query care citește `analytics_events` (evenimentele din NX-163) agregat per business + fereastră de timp. **Nu construiește UI** (frontend = Faza 5, repo separat) — expune funcții de query / eventual un endpoint intern de raport ce întoarce JSON.

Interogări (toate `WHERE business_id = $1 AND created_at în fereastră`):
- **Top zero-result** — `unmet_query reason=no_result` grupat pe `brand`/`category_key`, `count desc`.
- **Out-of-stock demand** — `unmet_query reason=out_of_stock` grupat, + join opțional `back_in_stock_subscriptions` pentru „N abonări".
- **Missing variants** — `unmet_query reason=missing_variant` grupat pe produs + `requested_attributes`.
- **Top requested brands/products** — `product_search.brand` + `agent_recommended.product_ids[]` grupat, `count desc`.
- **Drilldown** — pentru orice rând, întoarce `conversation_id[]` (limitat, cele mai recente) → suport pentru „arată-mi conversațiile". PII redactat: doar ids, nu corpuri.

`usage_daily` are un cititor de raport (Defect 3 din audit) — expune și un getter simplu peste rândurile de rollup pentru cadrul north-star (venit atribuit + split din NX-162).

## Test Cases
**Happy Path:** (a) 3 `unmet_query no_result` pe brand „Bioderma" → top zero-result îl arată cu `count=3` + `evidence_conversation_ids`. (b) top requested agregă `product_search.brand` corect.
**Edge Cases:** (a) fereastră fără evenimente → liste goale, nu crash/NULL. (b) drilldown cu multe conversații → limitat la N recente.
**Failure Cases:** (a) tenant B interoghează → nu vede cererea tenantului A (izolare). (b) event vechi fără câmpul nou (pre-NX-163) → sărit grațios, nu excepție.
