# NX-223 — Fingerprint-ul sesiunii de căutare e incomplet: `variant_label` + `product_name` lipsesc

**Owner:** Claude (build) / Codex (verify) · **Faza:** Web pilot (bug confirmabil) · **Zi/Ord:** track B, 1 · **Branch:** `fix/NX-223-session-fp-complete` · **Complexitate:** XS · **Estimare:** 1h
**Model recomandat:** Opus 4.8

## Goal
`_session_filters` canonizează query/categorie/brand/concerns/features/preț/sort/stoc
([catalog_tools.py:559-573](../src/tools/catalog_tools.py#L559-L573)) — dar `variant_label`
și `product_name` NU intră în fingerprint, deși `variant_label` e filtru DUR în ambele
retrievere ([catalog.py:415-416](../src/db/queries/catalog.py#L415-L416),
[catalog.py:917-918](../src/db/queries/catalog.py#L917-L918)). Consecința: „aveți în Warm
Beige?" cu același query text → fp identic → `continue_search_session` servește pool-ul
VECHI, nefiltrat pe variantă și fără marcajul `variant_match`. Taskul completează fp-ul cu
TOATE argumentele care afectează retrieval-ul.

## Business Context
Întrebarea de variantă („aveți nuanța X? mărimea Y?") e ultimul pas înainte de adăugarea în
coș — exact momentul în care un răspuns din pool-ul vechi (produse fără varianta cerută,
prezentate ca și cum ar avea-o) omoară conversia sau, mai rău, vinde produsul greșit.

## Technical Description
Regula care previne clasa întreagă de bug-uri: **fingerprint-ul conține ORICE argument care
schimbă setul de rezultate.** Concret:

```python
def _session_filters(
    a: SearchArgs, concern_keys: list[str] | None, features: list[str] | None = None
) -> dict[str, Any]:
    return {
        "query": a.query,
        "category": a.category,
        "brand": a.brand,
        "concerns": concern_keys,
        "features": features,
        "price_max": a.price_max,
        "sort_mode": a.sort_mode,
        "in_stock_only": a.in_stock_only,
        # NX-223: TOT ce filtrează retrieval-ul intră în fp — altfel rafinarea servește
        # pool-ul vechi. variant_label e filtru DUR (NX-135); product_name schimbă
        # diversificarea + named-miss disclosure.
        "variant_label": normalize(a.variant_label) if a.variant_label else None,
        "product_name": normalize(a.product_name) if a.product_name else None,
    }
```
- Normalizate (lower + fără diacritice) ca restul lanțului — „warm beige" ≡ „Warm Beige"
  nu trebuie să spargă sesiunea degeaba.
- Efect: rafinare cu variantă/nume → fp NOU → sesiune NOUĂ → retrieval proaspăt cu filtrul
  dur aplicat + `variant_match` marcat corect
  ([catalog_tools.py:811-813](../src/tools/catalog_tools.py#L811-L813)).
- Sesiunile vechi din state (fără cheile noi) produc fp diferit la prima căutare de după
  deploy → sesiune nouă, degradare naturală, fără migrare de state.
- Adaugă un **guard de completitudine** în teste: câmpurile din `SearchArgs` care ajung ca
  parametri de filtrare în `search_products_lexical`/`_semantic` trebuie să fie subset al
  cheilor din `_session_filters` — lista de excepții EXPLICITĂ (`limit`). Următorul argument
  de filtru adăugat fără fp → test roșu, nu bug tăcut.

**TurnContext:** niciun câmp nou; `state_patch.active_search` — owner neschimbat.
**Cost:** zero (schimbare pură de cod determinist).
