# NX-157 - Web Response Production Gate: contract API + evaluri web + anti-hallucination payload

**Owner:** TBD · **Faza:** P0/P1 · **Track/Wave:** Webwidget Production Readiness · **Branch:** `feat/NX-157-web-response-production-gate` · **Complexitate:** M · **Estimare:** 1-2 zile

## Goal

Defineste si valideaza calitatea raspunsurilor trimise catre frontendul web real. Acest repo nu construieste UI-ul dashboardului si nu trebuie sa refaca designul frontendului. Trebuie sa trimita payloaduri corecte, stabile si production-ready.

## Business Context

Frontendul separat poate randa frumos, dar daca backendul trimite produse gresite, preturi inventate, URL-uri goale sau raspunsuri generice, produsul tot nu e pregatit de productie. Gate-ul web trebuie sa masoare ce primeste frontendul: `content`, `products`, `suggestions`, `offer`, `comparison`, plus erori/fallbackuri.

## Scope

1. Freeze contract API cu frontendul:
   - endpoint oficial: de preferat `POST /web/chat` pentru pilot sincron;
   - schema payload;
   - campuri obligatorii vs optionale;
   - erori HTTP vs payload normalizat;
   - `trace_id` / `turn_id` daca este disponibil.

2. Fixtures JSON pentru frontend:
   - text only;
   - produse;
   - produse + suggestions;
   - offer CTA;
   - comparison;
   - no match;
   - fallback/error;
   - rate/budget exceeded.

3. Evaluri web:
   - 50-80 cazuri reprezentative;
   - multi-turn;
   - product IDs asteptate;
   - tool-uri asteptate;
   - constraints;
   - no hallucination pe pret/link/stoc/livrare.

4. Product correctness:
   - produs mentionat in `content` trebuie sa fie in `products` sau sa aiba sursa;
   - pret in text = pret din DB/card;
   - URL-uri valide;
   - no claims de stoc/livrare fara sursa.

## Implementation Steps

1. Documenteaza contractul in `docs/WEB-RESPONSE-CONTRACT.md` sau actualizeaza `docs/FRONTEND-CONTRACT-IZI.md`.
2. Adauga fixtures versionate pentru frontend.
3. Extinde `NX-145` / golden harness cu cazuri `channel_kind=webchat`.
4. Adauga checker specific pentru payload web: `content + products + offer + comparison`.
5. Ruleaza raport de productie pe cele 50-80 cazuri.

## Acceptance Criteria

- [ ] Frontendul are fixtures versionate pentru toate formele principale de payload.
- [ ] Minim 50 cazuri web trec prin eval harness.
- [ ] Checkerele prind pret inventat, produs inventat, URL gol si stoc/livrare fara sursa.
- [ ] Cazurile no-match folosesc redirect/clarify, nu recomandare ferma falsa.
- [ ] Contractul API poate fi consumat de frontend fara presupuneri fragile.
