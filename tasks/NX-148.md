# NX-148 — Conversation/User facts structurate (memorie peste ultimele 8 mesaje)

**Owner:** Claude · **Faza:** P1 · **Track/Wave:** Memory · **Branch:** `feat/NX-148-conversation-facts` · **Complexitate:** M · **Estimare:** 1-2 zile

## Goal
Ridică memoria de la „suficient pentru MVP" la personalizare reală (audit ARCH-REVIEW-2026-07 §5.8,
scor 6.8). Azi memoria = ultimele 8 mesaje (`context.py`) + `state` JSONB (ref-uri) + summary rolling +
extractor profil post-tur (`processor.py:697`). Limitări: summary-ul comprimă prea mult și pierde
fapte; preferințe/constrângeri/obiective nu-s modelate ca memorie separată cu confidence/source/last_seen.
Introduce un strat de **facts structurate** (conversation + user) extrase post-tur cu nano, injectate
ȚINTIT în prompt — **quick win, NU vector memory** (respins ca prematur de audit).

## Business Context
Fără facts persistente, botul „uită" că userul are ten sensibil sau buget 100 lei după ce iese din
ultimele 8 mesaje — re-întreabă, sună robotic, pierde vânzarea. Facts structurate = memoria care face
un asistent să pară că „te știe" între conversații (buget, tip de piele, mărime, branduri preferate,
restricții) — direct legat de calitatea recomandării (§5.7) și de rata de conversie.

## Technical Description

### Cele 4 straturi (audit §5.8) — mapare pe ce EXISTĂ
1. **Working memory** — intent curent + constrângeri + produse afișate → există (`ctx.state.search_constraints`, `displayed_products`, `active_search`).
2. **Conversation memory** — summary + facts ale conversației curente → summary există; **facts = NOU**.
3. **User memory** — preferințe stabile (buget, piele, mărime, branduri, restricții) → `contacts.profile` există parțial; **facts persistente = NOU**.
4. **Business memory** — politici, ton, produse promovate → DomainPack (NX-114) + `response_style_profile` (NX-144).

### Tabel nou `conversation_facts` (tenant-scoped, partiționabil ulterior)
```sql
conversation_facts(
  id, business_id NOT NULL, contact_id NOT NULL, conversation_id,
  fact_type,          -- ex. budget_max, skin_type, brand_pref, size, restriction
  fact_value,         -- text/jsonb
  confidence,         -- 0..1 (din extractor)
  source_message_id,  -- trasabilitate (mesajul din care a ieșit)
  first_seen_at, last_seen_at, expires_at,
  UNIQUE(business_id, contact_id, fact_type)  -- upsert: last_seen bump + confidence max
)
```
PII: `fact_value` NU conține telefon/id canal (rămân în `channel_identities`, P12). Whitelist de
`fact_type` per vertical (reutilizează mecanismul din NX-43 — chei permise), extractorul aruncă
tipurile necunoscute.

### Extractor (post-tur, extinde `_extract_profile_and_score`, `processor.py:697`)
Un singur apel nano post-tur (deja există pentru profil) întoarce 5-10 facts structurate → upsert în
`conversation_facts` (last_seen bump, expires refresh). Guardat de cost guard + shadow_mode (ca azi).

### Injectare țintită (`context.py`, `context_blocks`)
`facts_block(contact, conversation)`: citește facts relevante (user + conversation curentă, ne-expirate)
și adaugă un bloc compact în context (ca `customer_profile_block`/`state_block`). Bugetat (P4). NU
injectăm tot — doar facts cu confidence ridicat / relevante pentru ruta curentă.

## Principii CLAUDE.md aplicabile
- **P2:** un singur apel nano post-tur (extinde cel existent) — nu adaugă un punct LLM nou pe hot path.
- **P8 (state = ref-uri):** facts = valori mici structurate, nu obiecte; `conversation_facts` e tabel dedicat, nu blob în state.
- **P4:** `facts_block` bugetat în cod (cap de facts + chars).
- **P11:** facts cu locale-awareness la injectare (valori text în limba conversației unde e cazul).
- **P12:** `fact_value` fără PII; whitelist de tipuri.
- **P7:** toate query-urile `WHERE business_id = $1`.

## Implementation Steps
1. Migrare `docs/0NN_conversation_facts.sql` (tabel + index + grant `bot_runtime` + RLS `app.business_id`); rulată prin `scripts/migrate.py`.
2. `src/db/queries/facts.py`: `upsert_facts`, `fetch_relevant_facts` (tenant-scoped).

5. Kill-switch `conversation_facts_enabled` (default True; OFF → fără injectare + fără extragere).
6. Teste: extractor pe transcript → facts corecte; injectare bugetată; expirare; whitelist aruncă tip inventat; multi-tenant (facts altui business invizibile).

## Test Cases
**Happy:** transcript „buget 100 lei, ten sensibil" → 2 facts upsert; tur următor `facts_block` le injectează. **Edge:** fact expirat → nu se injectează; același fact re-menționat → `last_seen` bump, nu duplicat. **Failure:** extractor întoarce tip necunoscut → aruncat; cost guard peste buget → skip extractor, fără tăcere.
