# NX-146 — Turn Replay intern (reconstruiește un tur complet din analytics_events)

**Owner:** Claude · **Faza:** P1 · **Track/Wave:** Observability · **Branch:** `feat/NX-146-turn-replay` · **Complexitate:** M · **Estimare:** 1 zi

## Goal
Prima cărămidă de observabilitate „adâncă" (audit ARCH-REVIEW-2026-07 §5.12, scor 7.0): construiește
**Turn Replay** ÎNAINTE de tracing distribuit/enterprise. Pentru orice `turn_id`, reconstruiește
traiectoria completă a turului din `analytics_events` (deja corelate prin `turn_id`, NX-122) +
`messages`: envelope inbound, rută, evenimente de stagiu, tool calls + outputs (redactate), retrieval
IDs, reply final, rezultatul validatorului, cost/tokens/latență. Un CLI + view intern simplu — nu
enterprise, dar valoare imediată la debugging orice conversație problematică.

## Business Context
Condiția #6 pentru primul pilot plătit (audit §11): „logging/replay minim pentru orice conversație
problematică". Când un client raportează „botul a răspuns aiurea la clientul X, ora Y", azi reconstrucția
e manuală (grep prin loguri fără PII). Cu replay pe `turn_id`, un operator vede exact ce a decis fiecare
stagiu — reduce timpul de suport de la zeci de minute la secunde și alimentează cazuri golden (NX-145).

## Technical Description

### Sursa (append-only, deja există)
`analytics_events` are `turn_id` în coloană dedicată (`analytics.py:47`, NX-122) — filtrare/replay ieftin.
Evenimentele emise azi cu `turn_id`: `stage_completed` (runner), `tool_call` (args whitelisted +
n_results + latență + clasă eroare, `agent.py:1077`), `constraints_merged`, `llm_usage`, `reply_split`,
`turn_failed` (NX-140). Reply-ul final + envelope-ul inbound sunt în `messages` (corelate prin conversație + timp).

### Ce lipsește (de adăugat, redactat)
- **prompt_hash** + `retrieval_ids` pe stagiul agent: emit `agent_prompt` cu `prompt_hash` (sha256 al
  system+user rendered), `retrieval_ids: [product_id..]`, `validator: {ok, reasons}`. NU corpul promptului
  în DB (PII + volum); hash-ul permite corelarea cu o versiune de prompt din registry (viitor). Redactare
  ca la `tool_call` (P12 — zero telefon/PII).
- Opțional `prompt_rendered` redactat pe un TTL scurt / doar dev (kill-switch `replay_store_prompt_enabled` default OFF).

### Reconstrucția
`scripts/turn_replay.py <turn_id>`:
1. `SELECT ... FROM analytics_events WHERE business_id=$1 AND turn_id=$2 ORDER BY created_at`.
2. Join pe `messages` pentru inbound body + reply (redactate).
3. Asamblează un obiect `TurnTrace` (envelope → rută → stagii → tool calls → retrieval → reply → validator → cost/latență) → print JSON lizibil + tabel.
Un view intern minimal (reutilizează dashboard-ul de la NX-154) poate lista tururile cu `turn_failed` / cost mare / latență mare.

## Principii CLAUDE.md aplicabile
- **P10 (observabilitate din runner):** stagiile nu știu că sunt rejucate; replay-ul citește evenimentele emise de runner/executor.
- **P12 (PII un singur loc):** replay-ul redactează — zero telefon/PII; corpul promptului NU se persistă implicit.
- **P7:** query-ul de replay e `WHERE business_id = $1 AND turn_id = $2` (tenant-scoped, `admin_conn` DOAR pentru operațiuni cross-tenant de suport, cu audit).

## Implementation Steps
1. Emit `agent_prompt` (prompt_hash + retrieval_ids + validator result) din `agent_stage`/`_finalize*` prin `ctx.emit` (primește `turn_id`).
2. `scripts/turn_replay.py`: query pe `analytics_events` + `messages`, asamblare `TurnTrace`, output JSON/tabel.
3. Redactare centralizată (reutilizează redaction-ul din logger) + kill-switch `replay_store_prompt_enabled` (default OFF).
4. Teste: seed de events pentru un `turn_id` → replay reconstruiește ordinea stagiilor + tool calls; assert că nu apare niciun telefon.
5. (Opțional) buton „replay" în dashboard-ul pilot (NX-154).

## Test Cases
**Happy:** tur sales cu 2 tool calls → replay listează ambele + retrieval IDs + reply. **Edge:** tur `turn_failed` (NX-140) → replay arată eroarea + fallback-ul. **Failure:** `turn_id` inexistent → mesaj clar „niciun eveniment", exit code non-zero; PII injectat în body → redactat în output.
