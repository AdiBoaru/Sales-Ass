## Outcome verificabil

Fiecare turn web are un `TurnSnapshot` server-owned, imuabil și tenant-scoped. Browserul trimite numai
tipul suprafeței și identificatori opaci (`product_id`, `variant_id`, `category_id`, `cart_ref`), iar
backendul validează relațiile și rehidratează nume, URL, preț, stoc, variante, categorie și cart din
sursele canonice. „Produsul acesta” de pe PDP poate fi ancorat fără ca frontendul să construiască un
mesaj sau să trimită fapte comerciale. Nicio valoare afirmată de browser nu intră în prompt, ranking,
state sau ViewModel ca adevăr.

## Existing state și dovezi reproductibile

- `src/web/app.py:WebChatIn` acceptă token/session/message/`client_msg_id`/`id_token`, dar nu are context
  versionat pentru suprafață, produs, variantă, categorie ori cart.
- `src/models.py:ConversationState` păstrează `displayed_products` și `cart`, însă acestea descriu ce a
  emis asistentul, nu produsul paginii curente și nu sunt snapshot de request.
- `src/worker/context.py` construiește context din state/history; nu rehidratează un page anchor web.
- Follow-up-urile ordinale sunt rezolvate în `src/agent/deterministic.py` numai din
  `displayed_products`; un PDP cu zero produse afișate nu poate ancora „acesta”.
- Frontendul real are deja page/product state și un cart local, ceea ce creează tentația de a trimite
  nume/preț/stoc și de a face browserul al doilea source of truth.

## Dependencies

- **NX-228:** `WebTurnRequestV2.context` și limitele contractului sunt în main.
- **NX-229:** `business_id`, sesiunea, originul și identity sunt rezolvate server-side înainte de context.
- **NX-230:** raw body și orice metadata neîncrezătoare trec prin privacy boundary.
- **Soft:** NX-231 pentru checkouturi DB scurte; dacă nu este încă în main, acest card nu introduce
  niciun connection handle în snapshot și nu ține conexiunea peste compute.
- **Downstream:** NX-235 folosește snapshotul pentru referințe/memorie; NX-237 implementează adapterul
  canonic de cart; NX-238/240 consumă numai evidence rehidratat.

## Boundary frontend — nenegociabil

Frontendul detectează numai suprafața tehnică și forwardează ID-uri furnizate de host. Nu trimite și
nu calculează nume, descriere, preț, monedă, discount, stoc, rating, badge, criterii, total, categorie
dedusă, produs „selectat” semantic sau conținutul coșului. Nu concatenează „despre produsul X” în textul
utilizatorului. Backendul poate ignora sau respinge contextul invalid și livrează microcopy-ul aferent.
Frontendul nu repară un `context_ref` stale și nu face fallback la propriile date comerciale.

## Contract intern obligatoriu

### Input neîncrezător

`WebContextInputV2` rămâne forma NX-228 și acceptă numai:

- `surface`: enum finit;
- `product_id`, `variant_id`, `category_id`: ID-uri opace bounded sau `null`;
- `cart_ref`: referință opacă/versionată sau `null`;
- `locale`: locale allowlisted/negociat server-side;
- opțional `context_revision` tehnic, dacă hostul are o revizie stabilă; nu timestamp/preț.

`extra="forbid"`; body oversized sau câmp comercial adăugat (`price`, `stock`, `title`, `cart_items`)
este 422, nu silently trusted. Fingerprintul NX-232 include forma canonică safe a ID-urilor relevante.

### Output server-owned

```text
TurnSnapshot
├── tenant: business/channel IDs server-owned
├── actor: session/contact/identity refs safe
├── conversation: id + revision + state schema version
├── input: RawInbound request-scoped + SafeInbound persistable
├── surface: SurfaceContext(status=resolved|partial|stale|invalid)
│   ├── canonical product/category/variant evidence
│   └── source/fetched_at/freshness, fără connection
├── cart: CartSnapshotRef/resolved snapshot ori unavailable reason
├── memory: ConversationStateV2 snapshot (NX-235; adapter temporar până atunci)
├── displayed: ordine canonică de refs din state
└── deadline/correlation/pipeline_version
```

Snapshotul nu conține `asyncpg.Connection`, Redis client, lazy ORM, callback, raw JWT/action token sau
obiect mutabil partajat. Faptele comerciale au source/fetched_at și sunt rehidratate o singură dată per
turn ori printr-un `EvidenceBundle` explicit; promptul, tools și projectorul nu fac fiecare lookupuri
inconsistente.

### Validări de relație

- produsul aparține exact `business_id` derivat și este publicat/vizibil conform policy;
- varianta aparține produsului; category aparține/este compatibilă cu produsul dacă ambele sunt date;
- URL/image vin numai din catalogul server-side și trec validatorul NX-228;
- locale este intersecția dintre request allowlisted și channel/business support;
- cart ref este legat de aceeași sesiune/conversație/identity și versiune;
- un ID existent la alt tenant este tratat identic cu unul inexistent;
- `unknown` nu este convertit în `mismatch`; stale produce disclosure/refresh policy, nu fapt inventat.

## Data-readiness sub-plan obligatoriu

Contextul de pagină poate ancora un produs, dar nu garantează că toate facts necesare unei experiențe
de nivel iZi există. Înainte de a expune snapshotul către agent/projector:

1. Publică matricea `field → canonical source/query/adapter → freshness SLA → UNKNOWN behavior` pentru
   `price/list_price/currency`, stock per variantă, `rating/review_count/review_summary`, delivery promise
   + `verified_at` și promotion/voucher eligibility.
2. Măsoară coverage pe tenant/categoriile reale. Fixture-urile frontend, textul modelului și câmpurile
   vechi din conversation state nu sunt surse canonice.
3. Separă `Known(value,source,verified_at)`, `Unknown(reason)` și `Stale(age)`. Un `updated_at` generic nu
   dovedește automat că stockul, livrarea ori promoția sunt proaspete.
4. Rehidratează page product+variant/category în batch și stabilește un buget de query/provider calls;
   adaugă test 1/6/10 refs care detectează N+1.
5. Dacă price/stock/delivery/promo nu au feed/adaptor canonic, snapshotul marchează UNKNOWN, iar
   downstream NX-240 omite claimul și CTA-ul dependent. Nici modelul, nici frontendul nu inventează.
6. Rating/review summary apar numai din aggregate/content aprobat; lipsa nu devine `0 stele` sau review
   sintetizat. Promoțiile/voucherele nu se creează pentru paritate vizuală.

## Failure matrix

| Caz | Comportament obligatoriu |
|---|---|
| context absent pe home/other | snapshot valid fără page anchor |
| `surface=product`, product ID absent | `partial/invalid`; agent cere/continuă onest, fără presupunere |
| produs inexistent/nepublicat | aceeași semantică externă; zero evidence în prompt |
| ID valid la alt tenant | nu este găsit; zero existence leak |
| variantă de la alt produs | context invalid, event reason code, niciun preț/stoc folosit |
| category incompatibilă | category ignorată/refuzată conform policy, nu filtru hard accidental |
| browser trimite `price/stock/title` | 422 înainte de pipeline |
| catalog DB timeout | deadline bounded; snapshot `unavailable`; terminal view onest în downstream |
| preț/stoc se schimbă după accept | hydrate la execuție și freshness marcat; mutations reverifică în NX-237 |
| locale neacceptat | fallback server-owned determinist, nu copy ales de FE |
| cart ref stale/străin | unavailable/conflict fără conținutul coșului |
| refresh pe altă pagină, același turn ID | fingerprint conflict; nu reatașează context nou turnului vechi |

## Rollout și rollback

Începe cu parse+hydrate shadow și eventuri fără a introduce contextul în prompt. Activează pe tenant demo,
apoi pe un canary stabil după zero cross-tenant/mismatch. Flaguri separate pentru validation enforcement
și prompt exposure. Rollback scoate contextul din pipeline, dar păstrează requestul v2 și ledgerul; nu
revine la încrederea în price/stock/cart client-side. Context invalid nu poate fi „reparat” în frontend.

## Codex Attack Plan

1. Trimite un produs de la tenant B sub sesiunea tenant A și caută existence/facts în result, prompt și log.
2. Combină product A cu variant B și category C; verifică fail-closed, nu first-match.
3. Injectează preț/stoc/title/cart items extra și confirmă 422 înainte de fingerprint/pipeline.
4. Refolosește același turn ID după navigare la alt produs; trebuie conflict/replay, nu context mutat.
5. Inspectează snapshotul pentru connection, JWT/action token, raw URL/DOM sau obiect mutabil.
6. Oprește catalogul și confirmă terminal non-empty, fără fallback la datele browserului.
