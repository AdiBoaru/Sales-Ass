## Instrucțiune de execuție pentru `/task`

Acest card se execută în două faze și două worktree-uri. Prima invocare implementează și verifică
numai PR A backend pe branchul backend din metadata. După merge-ul lui, a doua fază folosește un
worktree separat din `Sales MVP Frontend Final` și implementează numai PR B frontend pe branchul
frontend din metadata. Nu există o stare validă în care Claude editează ambele repo-uri într-un
singur branch/PR. Fiecare fază rulează gate-ul repo-ului ei, iar gate-ul cross-repo final rulează după
ce ambele sides sunt disponibile.

## Outcome verificabil

Există un release gate reproductibil care pornește backendul v2 cu Postgres și Redis reale, dar cu
model/tool dependencies deterministe și fără cost LLM, pornește buildul frontend v2 și conduce
WebWidgetul prin browser. Gate-ul dovedește end-to-end contractul, exact-once/replay, recovery după
refresh și restart, două taburi, acțiuni opace, frontend pasiv, accesibilitate și failure behavior.

Același manifest de schemă/fixtures/hash este consumat de ambele repo-uri. Driftul rupe CI. Niciun
test nu trece printr-un mock care ocolește exact componenta pe care pretinde că o verifică.

NX-247 nu este o singură suită happy-path. Este poarta obligatorie înainte de canary NX-249.

## De ce este necesar

## Boundary frontend pasiv — ce trebuie să dovedească gate-ul

Gate-ul nu se limitează la source grep. El demonstrează comportamental că:

- schimbarea display strings în ViewModel schimbă UI exact, fără recalculare;
- ordinea blocks/items/actions din backend este ordinea DOM;
- labelul unei acțiuni nu este request payload; tokenul opac este trimis byte-identic;
- UI nu adaugă produse, criterii, progress, disclaimer, fallback sau cart receipt absent din backend;
- preț/discount/stoc/rating/comparison cells nu sunt derivate din raw fields;
- refreshul reconstruiește transcriptul din server, nu din localStorage;
- cart/wishlist global demo nu este mutat de widget;
- malformed/unknown contract produce technical unavailable, nu best-effort business UI.

Testele nu au voie să „ajute” frontendul prin injectarea directă de props normalizate dacă scenariul
pretinde că verifică wire decoderul. Pentru testele de componente izolate, fixtures sunt permise; pentru
cross-repo E2E, payloadul trebuie să traverseze endpointul și decoderul real.

## Strategia de harness — fără LLM real și fără bypass fals

### Nivel 1: backend integration real

Pornește aplicația FastAPI reală cu:

- Postgres real, migrări Stage 1 aplicate prin `scripts/migrate.py`;
- Redis real;
- edge/session/CORS/ledger/executor/projector v2 reale;
- model/embedding/tool extern înlocuite prin dependency injection test-only;
- clock/IDs controlabile doar prin fixture seam, nu prin production endpoint;
- două tenants/cataloguri sintetice distincte.

Fake modelul întoarce planuri/tool calls deterministe; projectorul real construiește ViewModelul.
Pentru a acoperi fiecare block vizual fără prompt fragil, harnessul poate avea și scenarii projector
fixture, dar acestea trebuie marcate separat și tot trebuie să treacă prin persistence/result endpoint.

Orice `__test__` control route:

- trăiește exclusiv în `tests/e2e/stage1_app.py`, nu în routerul production;
- refuză pornirea dacă `ENV != test`;
- se leagă numai la loopback;
- cere un secret random per proces pentru mutarea scenariului;
- nu este inclus în Dockerfile/deploy image production.

### Nivel 2: browser real

Frontendul rulează prin Vite preview/build v2, nu component mount izolat. Playwright:

- deschide originul local allowlisted;
- folosește network/browser APIs reale pentru bootstrap/POST/SSE/poll;
- poate întrerupe o conexiune pentru response-loss/offline tests, fără a modifica body/ID;
- citește numai selectors/roles stabile;
- verifică backend probe read-only pentru execution count/result/receipt unde este necesar.

### Nivel 3: contract drift

Manifestul canonic conține cel puțin:

```json
{
  "schema_version": "web-view.v2",
  "schema_sha256": "…",
  "fixtures_sha256": "…",
  "backend_commit": "…",
  "generated_at": "deterministic-or-omitted"
}
```

Frontend CI checkout-uiește backend `main`/SHA declarat, rulează generator/checkerul NX-242 și pică
dacă schema, hashul, fixtures sau validatorul generated diferă. `generated_at` nu poate face artifactul
nondeterminist.

## Race și failure matrix obligatorie

| ID | Injecție/cursă | Așteptat backend | Așteptat frontend |
|---|---|---|---|
| R1 | double click/Enter+click | un ledger row/o execuție | un POST logic, busy imediat |
| R2 | două taburi simultan | un active turn serial; rezultat/reject tipizat | ambele converg la snapshot |
| R3 | response 202 pierdut | result rămâne durabil | lookup same client ID, zero turn nou |
| R4 | refresh în `working` | turn continuă | bootstrap/recovery, input disabled |
| R5 | worker kill după claim | lease/fencing/reaper recuperează | wait/recovery, apoi un terminal |
| R6 | worker vechi revine după lease | commit fenced respins | nu vede rezultat stale |
| R7 | SSE disconnect/duplicate/gap | backlog/status lookup coerent | dedupe/refetch, revision monotonic |
| R8 | Redis restart | ledger DB rămâne adevăr | poll/recover; niciun blank |
| R9 | DB transient la commit | retry bounded/terminal safe | nu afișează succes înainte de persist |
| R10 | 403/session expiry | renewal păstrează binding | lookup same turn/conversation |
| R11 | 409 active turn | referință la active turn | attach, nu turn nou |
| R12 | 429 rate/cost | zero executor/model call | ViewModel/error tehnic randabil |
| R13 | 413/422 | zero storage/pipeline | input/retry conform error contract |
| R14 | timeout model/tool | deadline fallback + terminal persistat | atomic result, nu token streaming |
| R15 | malformed payload interceptat | N/A/test proxy | decoder fail-closed, no business UI |
| R16 | major/hash drift | CI/runtime contract error | fără auto-v1/best-effort |
| R17 | stale/tampered action | zero mutație, error terminal | token neschimbat, fără toast fals |
| R18 | action wrong tenant/conversation | 403/409 tipizat, zero leak | nu afișează data celuilalt tenant |
| R19 | commerce action retry | același receipt, o mutație | un singur succes server-owned |
| R20 | New chat în working | reset respins/disabled | control inactiv; result nu se reatașează greșit |
| R21 | offline 30s apoi online | turn/result retenționat | recovery fără transcript local |
| R22 | progress out-of-order | sequence/revision detectabil | nu regresează status/view |

Fiecare rând are un test automat sau, dacă o limitare de platformă îl face exclusiv manual, owner,
comandă și evidence obligatorii în manifest. P0 R1–R20 nu pot fi marcate „flaky/quarantine”.

## Test Cases

### Backend harness self-test

- refuză pornirea la `ENV != test` și binding non-loopback neaprobat;
- fake model/tool counters dovedesc zero network/cost;
- scenariul setat este izolat per test/tenant și resetat între teste;
- probes sunt tenant-scoped și read-only;
- migrations pornesc pe DB goală și schema este la zi;
- două tenants cu IDs similare nu văd turns/results/actions reciproc;
- manifest/schema/fixtures hash sunt deterministe.

### Contract cross-repo

- schema backend = schema frontend byte/hash conform algoritmului NX-228;
- validator generated este la zi;
- toate fixtures backend validează în Python și în decoderul JS;
- backend projector output din scenariile canonice validează în browser;
- modificarea artificială a oricărui artifact rupe jobul.

### Browser happy/passive

- bootstrap, submit, progress real, result atomic, second turn;
- toate block types și ordinea;
- exact display strings pentru price/discount/status/rating;
- nicio mutație cart/wishlist locală;
- action label schimbat cu token constant produce același request;
- ViewModel fără un element nu îl face să apară client-side.

### Browser reliability/security

- R1–R22;
- origin neallowlisted, token invalid, session binding greșit;
- cross-tenant action/context/result;
- body oversized și nested payload;
- refresh/back/forward/route navigation și multiple tabs;
- server/Redis/worker controlled restart.

### Accessibility/browser matrix

- Axe zero serious/critical pentru stările canonice;
- keyboard/screen-reader semantics din NX-245;
- Chromium pe fiecare PR;
- Firefox + WebKit pe main/nightly și obligatoriu înainte de NX-249 release;
- viewport 320/360/390/452/desktop, zoom/reduced motion/high contrast smoke.

### Quality/grounding invariants

- product/view IDs provin din catalogul sintetic tenantului corect;
- displayed prices/status/URLs egalează snapshotul canonic folosit de projector;
- hard constraint fixtures nu sunt încălcate;
- terminal views nu sunt goale;
- response nu conține chain-of-thought;
- output quality determinist nu substituie evalul blind NX-210/239, dar îl protejează de regresii de
  integrare.

## Metrici, SLO și praguri de gate

NX-247 nu inventează praguri noi. Citește fișierul/contractul de thresholds ratificat de NX-241/246
și verifică automat:

- submit→accepted latency;
- accepted→terminal end-to-end p50/p90/p95 conform scope test;
- recovery success rate și recovery duration;
- duplicate execution/receipt count = **0**;
- empty terminal views = **0**;
- contract decode/hash errors = **0** pe happy suite;
- hard constraint/grounding violations = **0** pe fixtures release;
- cross-tenant leaks = **0**;
- Axe serious/critical = **0**;
- frontend business-boundary violations = **0**;
- DB connections held over LLM/HTTP wait = **0**, din NX-231 instrumentation;
- traces complete pentru toate scenariile obligatorii, fără PII.

Fișier recomandat, dacă NX-246 nu a creat deja unul:
`qa-suite/stage1/web-v2/gate-thresholds.json`. Nu duplica thresholds în Python, JS și YAML; un singur
artifact, validat în ambele repo-uri.

## Politica de flake

- R1–R22, contract, tenant isolation și actions: `retries=0`; orice flake blochează merge și se repară;
- browser engine-specific poate avea un retry numai după finding documentat, owner și termen, niciodată
  pentru correctness/idempotency;
- fără `test.skip`/`fixme` pe P0 în branchul de release;
- timeouts per test sunt bounded și raportate; mărirea timeoutului nu este fix fără root cause;
- nightly failure creează incident/task înainte de NX-249, nu este ignorat ca „CI noise”.

## Rollout și rollback

## Definition of Done

- [ ] Există două PR-uri separate, cu PR A backend merged înainte de PR B frontend.
- [ ] Harnessul folosește edge/ledger/executor/projector reale și provider extern fake test-only.
- [ ] Harnessul nu poate porni în production/non-loopback și nu intră în production image.
- [ ] Zero apeluri/cost LLM/embedding/commerce în toate suitele.
- [ ] Schema/hash/fixtures/validator sunt verificate cross-repo și driftul rupe CI.
- [ ] Toate scenariile canonice și R1–R22 sunt automate sau au justificare/evidence explicită.
- [ ] Response loss, refresh, două taburi, worker/Redis restart și fencing sunt dovedite end-to-end.
- [ ] Action token passthrough, stale/tampered/cross-tenant și receipt idempotency sunt dovedite.
- [ ] Frontendul pasiv este verificat static și comportamental; zero logică business client.
- [ ] Axe/keyboard/responsive gates trec; zero serious/critical.
- [ ] Pragurile NX-241/246 trec dintr-un singur thresholds artifact.
- [ ] Artifact redaction/deny-sentinel și retention sunt testate.
- [ ] P0 rulează cu retries zero și fără skips/quarantine.
- [ ] Backend ruff/format/pytest și frontend lint/typecheck/unit/build/Playwright sunt verzi.
- [ ] Runbookul local este copy/paste executabil pe un checkout curat.
- [ ] Manifestul final conține perechea exactă de SHAs certificată pentru NX-249.

## Codex Attack Plan

1. Înlocuiește schema frontend cu un byte; cross-repo gate trebuie să pice înainte de browser tests.
2. Verifică harnessul: finding critic dacă un env flag production poate activa fake provider/test route.
3. Blochează response după accept; orice al doilea execution/model counter este finding critic.
4. Omoară workerul după claim și lasă workerul vechi să revină după lease; exact un commit terminal.
5. Trimite simultan din două taburi și inspectează DB, nu doar UI; două active executions = finding.
6. Refolosește action token în alt tenant/conversation și apoi retry în tenantul corect; zero leak, un
   receipt total.
7. Schimbă display price/discount/tone/order în projector fixture; UI trebuie să le reflecte exact.
8. Omite cart receipt/success block; orice localStorage mutation/toast frontend este finding critic.
9. Pune sentinel în token/text, forțează failure și descarcă toate artifacts; sentinel prezent = leak.
10. Rulează testele cu network deny; orice DNS/provider attempt este scope violation.
11. Caută `waitForTimeout`, retries, skip/fixme și teste care injectează direct props în fișierele E2E;
    justificare absentă = gate fals.
12. Rulează Axe și keyboard pe comparison maxim la 320px/400%; content/action inaccesibil = finding.

## Out of Scope
