## Outcome verificabil

Un mesaj web trece printr-o singură frontieră privacy înainte de persistență, moderation, history,
prompt, tool, cache, analytics și trace. Textul brut există numai în memoria limitată a turului atât
cât este necesar; reprezentarea persistabilă este redactată/tokenizată și nu poate reintroduce PII
în turnurile următoare.

## Existing state și finding

- `processor.py` inserează mesajul inbound înainte ca gates să termine privacy processing.
- `gates.py` documentează că storage rămâne raw, iar istoria poate reintroduce informația.
- `context.py` trimite corpurile mesajelor istorice către triage/agent.
- moderation rulează înaintea mascării în unele căi.
- raw order/context payload poate ajunge în coadă/storage.

Acest card respectă D6: agentul principal poate vedea query-ul brut **în memoria turului**, însă raw
query nu este persistat sau exportat. `SafeQuerySpec` și textul redactat sunt singurele forme pentru
telemetrie/persistență.

## Dependencies

## Boundary frontend — nenegociabil

Frontendul nu face privacy enforcement și nu este sursa adevărului pentru redacție. Poate preveni
accidental autofill sau poate afișa copy primit, dar backendul tratează tot inputul drept untrusted.
Nu i se cere FE să recunoască telefon, email, adresă, nume, date medicale sau secrets.

## Contract intern propus

- `RawInbound`: body original, request-scoped, interzis în `repr`, logs, events și DB;
- `SafeInbound`: text tokenizat/redactat + locale + categorii detectate + correlation IDs;
- `SensitiveTokenMap`: request-scoped, nu se serializează; necesar numai dacă răspunsul legitim
  trebuie să reflecte o valoare către același utilizator;
- `RuntimeQuerySpec`: poate conține raw în memorie;
- `SafeQuerySpec`: singura formă persistabilă/telemetrizabilă;
- `SafeHistoryMessage`: body safe; builderul nu poate accepta direct row DB raw.

Categorii minime: telefon, email, adresă, CNP/card/IBAN, auth/API secrets, order/customer identifiers,
nume declarat în context sensibil, date medicale/safety și prompt-injection exfiltration markers.

## Scope și fișiere

### Create/Modify

- `src/privacy/` sau modulul canonic existent: contracts, detectors, tokenizer, policy;
- `src/web/app.py`: privacy seam imediat după validarea structurală;
- `src/worker/processor.py`: persistă numai safe body/payload;
- `src/worker/stages/gates.py`: consumă obiectul safe/raw după politica explicită;
- `src/worker/context.py`: numai `SafeHistoryMessage`;
- `src/worker/stages/triage.py`, `agent.py`: raw numai request memory, fără event;
- `src/cache/*`, `src/evals/*`, `src/worker/aftercare.py`: contract safe-only;
- logger/OTel sanitizers și tests dedicate.

## Out of Scope

- implementarea unui vault raw; dacă devine necesar, card separat cu KMS, TTL, audit și DPA;
- colectarea documentelor de identitate sau a plăților;
- schimbarea business rules de safety/contraindicații;
- redacție client-side.

## Pași de implementare

1. Desenează data-flow pentru body/payload/history din ingress până la fiecare sink.
2. Definește tipurile care fac imposibilă trecerea accidentală a raw către query/logger/event.
3. Mută DLP imediat după auth/body-size validation și înainte de insert/moderation/cache.
4. Rulează moderation pe forma cerută de threat model fără a persista raw; documentează ordinea.
5. Persistă `SafeInbound`; dacă businessul cere audit raw, oprește cardul și cere decizie vault.
6. Înlocuiește history builder cu safe rows și backfill/redaction pentru datele demo existente numai
   prin script dry-run + aprobarea userului; nu șterge automat date live.
7. Asigură că error objects/exceptions nu includ raw body sau request payload.
8. Interzice raw în analytics, cache keys, traces, idempotency fingerprint și result ledger.
9. Adaugă static/AST guard unde este practic: evenimentele acceptă numai payload safe allowlisted.
10. Documentează drepturile GDPR și retenția pentru noile tabele Stage 1.

## Failure matrix

| Caz | Comportament |
|---|---|
| detector timeout/crash | fail-safe: nu persistă raw; răspuns terminal onest |
| text numai PII | safe placeholder; agentul nu repetă valoarea |
| history vechi raw | exclus/redactat la load; alertă fără conținut |
| secret într-un tool error | sanitizer înainte de log/trace/result |
| tokenizare produce coliziune | token IDs request-scoped și type-safe |
| PII în context page/cart | IDs validate și rehidratare; fără label/address brut |
| retry același turn | fingerprint safe/HMAC; raw nu intră în ledger |

## Test Cases

- unit pe fiecare categorie cu formate RO/HU/EN și typo-uri;
- property/fuzz: unicode, separator zero-width, JSON nested, long text;
- integration: insert messages/turn/history și assert zero PII;
- prompt capture: query curent poate fi disponibil agentului conform D6, dar history/telemetry sunt safe;
- log/trace capture pe exception și timeout;
- tenant/GDPR export/erase paths pentru noile obiecte;
- regression safety: contraindicațiile canonice rămân disponibile fără text medical raw persistent;
- gate complet.

## Events low-cardinality

- `privacy_redacted{categories,count_bucket}`;
- `privacy_guard_failed{stage,reason}`;
- `privacy_legacy_row_blocked{table}`.

Niciun event nu conține fragment, hash reversibil, lungime exactă rară sau identificator extern.

## Rollout/rollback

Shadow-ul poate compara numai counts/categorii, nu text. Enforcementul pornește pe web demo înainte
de canary. Rollbackul nu poate reactiva persistența raw implicit; privacy boundary este fail-safe și
rămâne activă chiar dacă pipeline v2 este oprit.

## Definition of Done

- [ ] Frontiera DLP precedă orice storage, prompt-history, cache, log, trace și analytics sink.
- [ ] Raw query trăiește numai request-scoped conform D6 și nu este serializabil accidental.
- [ ] Istoricul este construit exclusiv din reprezentări safe.
- [ ] Mesajele/payloadurile noi persistate nu conțin PII din corpusul adversarial.
- [ ] Detector indisponibil nu duce la persistarea raw.
- [ ] Idempotency/result ledger nu conține raw sau PII.
- [ ] GDPR export/erase și retenția sunt documentate/testate.
- [ ] Zero cerințe de privacy logic în frontend.
- [ ] Gate complet verde.

## Codex Attack Plan

1. Injectează PII în body, JSON nested, error de tool și prompt-injection; caută valoarea în toate sinks.
2. Creează history legacy raw și verifică să nu ajungă în captured prompt.
3. Oprește detectorul și confirmă fail-safe, nu fallback la raw.
4. Verifică să nu existe `log.*(body/payload/token/claims)` pe căile noi.
