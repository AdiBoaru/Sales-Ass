## Outcome verificabil

Pentru orice mesaj web nontrivial există un singur agent principal care înțelege toate obligațiile,
apelează tools și emite direct un `AnswerPlanV2` grounded. Control plane-ul determinist păstrează auth,
privacy, safety, idempotency, hard constraints, exact fast paths și validarea; nu există un șir de
triage model → tool-loop writer → rich writer → AnswerPlan writer care pierde nuanța sau rescrie răspunsul.

Răspunsul rezultat este direct, natural și coerent cu un om normal: răspunde întâi la întrebare, nu
repetă șabloane/greeting/disclaimere, păstrează și rectifică cerințele, explică recomandările prin dovezi
concrete, pune maximum o clarificare cu information gain mare și spune onest când nu are rezultat/date.
Producția nu este activată până când NX-246 pairwise+holdout demonstrează câștig și zero regresii hard.

## Boundary frontend — nenegociabil

Frontendul nu detectează intent, nu alege fast path/brain/model/tool, nu combină mesaje, nu decide când
să clarifice și nu rescrie tonul. Nu păstrează constraints și nu ascunde no-results. El afișează
ViewModelul NX-240 și retransmite input/action. „Natural” este proprietatea răspunsului backend, nu un
efect de typing delay, texte rotative sau șabloane client-side.

## Arhitectura obligatorie

```text
Durable TurnSnapshot
  → deterministic control plane
      auth/privacy/safety/deadline/state/action normalization
      exact-complete fast-path decision
  → MainBrain (numai dacă fast path nu acoperă TOATE obligațiile)
      tool calls prin registry typed + RetrievalPort/CartService
      final structured AnswerPlanV2 în aceeași buclă
  → deterministic plan/evidence/state/action validators
  → selective critic cu codes-only (doar triggeri de risc)
  → cel mult un repair bounded al aceluiași brain, dacă policy permite
  → NX-240 grounding + WebViewModel projection + terminal commit
```

„Single brain” înseamnă un singur writer semantic principal. Validatorul, MatchGate, safety gate,
reference resolver, state reducer și projectorul rămân deterministici și au drept de veto. Criticul nu
scrie răspunsul; returnează reason codes. Runtime modelul nu este hardcodat de modelul Claude folosit la
coding: se selectează numai prin eval blind, cu model/prompt/tool schema version capturate.

### Fast-path policy

Un fast path poate finaliza turnul numai dacă un recognizer determinist dovedește:

- inputul este dintr-o clasă exactă/allowlisted;
- toate obligațiile au răspuns complet și grounded;
- nu există mixed intent, negare, referință ambiguă, correction, safety ori constraint neprocesat;
- copy-ul este authored/canonic și state/action effects trec prin aceleași reducers/services.

Candidați: greeting pur, alias exact aprobat, FAQ exact cu evidence curent, action kernel exact,
show-more determinist și handoff/order gates. Semantic cache/FAQ similar nu early-exit-ează un mesaj mixt.
`FastPathDecision` conține `covered_obligations`, `uncovered`, `evidence_refs`, reason și version.

### `AnswerPlanV2`

Extinde NX-211 versionat și `extra=forbid`, cu caps:

- `intent_summary` safe și `obligations[]` (answer/recommend/compare/explain/action/clarify/safety);
- `direct_answer`/lead scurt, în limba userului;
- `claims[]` atomice cu `claim_type`, text/value, evidence IDs și freshness requirement;
- `recommendations[]` refs + motive concrete legate de needs și evidence, fără generic „ideal”;
- `comparison` refs/axes/cells sourced, fără winner inventat;
- `constraints_applied[]`, `unknowns[]`, `relaxations[]` explicite; hard relaxations interzise;
- `clarification?` unică: întrebare, target need, information-gain reason, opțiuni action intents;
- `no_results?`: `no_match|insufficient_data|dependency_unavailable`, criterii și alternative safe;
- `state_update_proposal`, `action_intents[]`, `disclosures[]`, `handoff?`;
- `style_signals` limitate (tone/verbosity), fără CSS/layout/remote UI.

Planul nu conține CoT, scoruri psihologice, fapte fără evidence, raw tool payload sau instrucțiuni către
frontend. Claimurile comerciale critice sunt facts typed; proza naturală este validată față de ele.

## Contract de calitate umană

Aceste criterii sunt evaluate atât automat unde este obiectiv, cât și blind pairwise uman:

1. **Direct:** primul bloc răspunde la întrebarea principală; nu începe cu recapitulări/greeting inutile.
2. **Natural:** română fluentă, variație controlată de context, fără sloganuri, „Sigur!”, emoji sau
   disclaimere repetitive la fiecare turn; nu pretinde că este om.
3. **Coerent:** păstrează nevoile active și recunoaște explicit corecția/revocarea relevantă.
4. **Concret:** fiecare „de ce recomand” se leagă de o proprietate/review aggregate/fapt și de nevoia
   userului; zero motive generice care ar putea descrie orice produs.
5. **Clarifică rar:** maximum o întrebare, numai dacă răspunsul schimbă material safety/set/ranking;
   altfel răspunde best-effort și marchează assumption/unknown.
6. **No-results onest:** distinge zero match de coverage necunoscut/provider indisponibil; nu încalcă hard
   constraints ca să afișeze produse și nu inventează stoc/preț/promo.
7. **Obligații complete:** mixed intent primește toate sub-răspunsurile într-o ordine utilă, fără ca un
   FAQ/greeting să întrerupă restul.

iZi/eMAG este numai benchmark comportamental pentru directness, naturalețe, continuitate și utilitate.
Nu este contract, sursă factuală, prompt de copiat sau permisiune de a reproduce texte/branding/UX
proprietar. Golden setul folosește propriul catalog și propriile formulări.

5. Introdu `FastPathDecision`; fiecare stage existent fie dovedește `complete`, fie produce semnal/context

6. Modifică tool loop astfel încât ultimul răspuns al aceluiași MainBrain să fie `AnswerPlanV2` structurat.

7. Leagă `RetrievalPort`: selectorul NX-238 furnizează current live pe NO-GO și candidate numai pe GO.
   Brain/promptul nu știe și nu alege providerul.
8. Leagă StateV2 reducer: brainul propune updates, reducerul decide. Include revocations și constraints în

9. Implementează quality checks: direct answer presence, repeated n-grams/template fingerprints între
   turnuri, maximum o clarification, evidence per concrete reason, honest no-results taxonomy.
10. Păstrează critic selectiv: rulează numai la triggeri (safety, mixed obligations, low coverage,
    commercial claims); returnează codes. Un singur repair bounded al MainBrain, apoi fallback determinist.
11. Versionează system prompt/tool schemas/model/runtime settings și capturează hashes în ledger/events.
12. Rulează offline golden și NX-246 blind pairwise/holdout. Nu activa producția din acest PR.

## Failure matrix

| Caz | Comportament obligatoriu |
|---|---|
| greeting + întrebare produs | greeting fast path incomplet; MainBrain răspunde întrebării |
| FAQ + recomandare în același mesaj | ambele obligations acoperite, nu primul reply wins |
| corecție „nu 100, maxim 70” | state proposal supersede; plan folosește 70 |
| hard constraint fără match | no-results onest; nu relaxează/ascunde constraintul |
| facet/stock/price UNKNOWN | declară limita/omite claim; nu tratează ca mismatch/known |
| referință ambiguă | maximum o clarificare cu opțiuni grounded |
| clarificare cu gain mic | best-effort direct, assumption/unknown explicit |
| tool timeout | plan/fallback terminal grounded pe evidence disponibil, fără tăcere |
| SearchEntities NO-GO | CurrentLiveRetrievalAdapter; brain funcționează |
| plan JSON invalid | repair bounded o dată, apoi fallback determinist non-empty |
| critic indisponibil | validator determinist rămâne; high-risk claim omis/fallback, nu fail-open |
| model inventează action/tool/fact | schema/registry/evidence guard reject |
| response repetă template în conversație | quality check/event și candidate pierde eval pairwise |

## Rollout și rollback

Codul intră dark, apoi shadow offline/online fără a livra răspunsul candidate. NX-246 preregistrează și
rulează pairwise+holdout; doar verdictul explicit GO permite canary. Canary este stable pe business+
conversation și capturează pipeline version la accept. Search provider urmează separat verdictul NX-238.
Rollback revine la pipelineul current și current retrieval pentru trafic nou, dar lasă executorul să
termine turele acceptate pe versiunea capturată. Orice hard violation, factual invention sau P6 blank
declanșează kill switch; nu se „repară” în frontend.

## Codex Attack Plan

1. Combină salut+FAQ+recommendation+constraint într-un mesaj și caută early exit/obligation lipsă.
2. Corectează/revocă o nevoie, apoi injecteaz-o în history; planul nu trebuie să o reînvie.
3. Furnizează zero match și cere „oricum ceva”; hard constraint nu poate fi relaxat silent.
4. Forțează fiecare model/tool/critic să timeout/returneze invalid și verifică un singur fallback non-empty.
5. Numără writerii și LLM calls; orice triage/rich/plan writer concurent nejustificat este finding.
6. Rulează pairwise blind pe răspunsuri repetate; caută formule/copieri iZi, generic reasons și clarificări inutile.
