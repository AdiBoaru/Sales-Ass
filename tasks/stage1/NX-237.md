## Outcome verificabil

WebWidgetul folosește un singur cart service server-side. Atât action clicks, cât și tool calls LLM
trimit aceeași comandă typed (`product_ref`, `variant_ref`, `quantity`, expected version), iar serviciul
rehidratează și reverifică produsul, varianta, prețul, stocul și safety înainte de mutație. Orice succes
are un receipt idempotent și un `CartSnapshot` versionat; retry-ul nu dublează cantitatea sau checkoutul.
Frontendul nu păstrează un coș paralel și nu calculează linii, totaluri, reduceri ori disponibilitate.

## Existing state și dovezi reproductibile

- `src/models.py:ConversationState.cart` este o listă JSONB cu `product_id`, `variant_id`, `name`,
  `price`, `quantity`; facts comerciale pot deveni stale în memoria conversației.
- `src/tools/commerce_tools.py:cart_add_tool` copiază preț/nume în `state_patch`, calculează totalul local
  și limitează coșul; nu există remove/set quantity/clear versionate sau mutation receipt.
- `src/tools/commerce_tools.py:checkout_link_tool` rehidratează unele produse și scrie în
  `checkout_links`, dar semantics exact-once față de adaptorul extern nu este generalizată.
- `src/db/queries/commerce.py:create_checkout_link` folosește `ref_code=turn_id` pentru idempotency,
  însă aceasta nu acoperă toate mutațiile de coș și action replay.
- Frontendul demo are propriul cart/localStorage; dacă asistentul îl tratează ca adevăr apare split-brain
  între UI, `ConversationState.cart` și checkout.
- Catalogul are price/variant/review fields, dar nu există un contract unificat de freshness pentru
  stock, delivery promise, voucher/promo și `verified_at`.

## Dependencies

- **NX-234:** contextul și toate product/variant refs sunt server-rehidratate și tenant-scoped.
- **NX-236:** action ID, source binding și one-shot consume există; receiptul se leagă de action/turn.
- **Transitive NX-232/NX-231:** result+state+receipt seam atomic și conexiuni scurte sunt disponibile.
- **Reused:** NX-79/163/173 și `commerce_tools.py` pentru policy/safety/checkout attribution; nu se ocolesc.
- **Downstream:** NX-240 proiectează `cart_summary` și CTA numai din snapshot/receipt.

## Boundary frontend — nenegociabil

Frontendul nu trimite cart lines, preț, voucher, stoc, total sau mutation kind interpretat. El trimite
numai tokenul opac NX-236 și afișează `cart_summary`/receipt/error ViewModel. Nu actualizează optimistic
localStorage, nu reconciliază versiuni, nu aplică voucher și nu confirmă „adăugat”. Composerul/controls
rămân inactive până la terminal. Coșul global demo poate exista în site, dar WebWidget nu îl citește și
nu îl modifică prin logică ascunsă; integrarea cu el cere adaptor host/server separat și contract explicit.

## Port și contracte obligatorii

### `CommerceFacts`

Pentru fiecare product+variant, backendul produce fapte typed cu source și freshness:

- `price.current`, `price.list_price`, `currency`, `verified_at`, `status=known|unknown|stale`;
- `availability.status=in_stock|out_of_stock|preorder|unknown`, quantity/cap numai dacă sursa permite;
- varianta canonică, atribute/label server-owned și relația variant→product;
- `rating`, `review_count`, `review_summary` numai din aggregate/content aprobat, cu source/freshness;
- `delivery.promise_text`/interval numai din adaptor canonic și `verified_at`;
- `promotion`/`voucher` numai dacă există regulă canonică aplicabilă, interval și eligibility verificabile.

Dacă sursa/adaptorul lipsește sau este stale peste SLA, statusul este `UNKNOWN`: modelul nu afirmă
valoarea, projectorul omite câmpul/CTA-ul dependent și livrează disclosure onest unde este util.
Nu există promoții, vouchere, ETA, stock sau reduceri generate din prompt, fixture UI ori heuristici.

### `CartService`

```text
get_snapshot(actor, cart_ref?) -> CartSnapshot(version, lines, totals, facts_status)
mutate(actor, CartCommand, expected_version, idempotency_key) -> MutationReceipt + CartSnapshot
create_checkout(actor, cart_ref, expected_version, idempotency_key) -> CheckoutReceipt
reconcile(receipt/external_key) -> canonical status
```

Commands allowlisted: `add`, `set_quantity`, `remove`, `clear`, `checkout`. Inputul conține refs și
quantity bounded, nu preț/nume/discount. Toate intrările (action kernel și LLM tool) folosesc exact acest
service; toolul nu poate produce `state_patch.cart` direct.

### Persistență logică

`conversation_carts` minimum:

- `id`, `business_id`, `conversation_id`, actor/session scope după policy;
- `version`, `status=active|checked_out|expired`, `currency?`, `external_cart_ref?` safe;
- created/updated/expires timestamps, fără PII.

`conversation_cart_items` minimum:

- `business_id`, `cart_id`, `product_id`, `variant_id`, `quantity`, added/updated turn refs;
- UNIQUE cart+product+variant; refs și quantity, nu cache permanent de name/price/stock.

`commerce_action_receipts` minimum:

- `id`, `business_id`, conversation/cart/action/target turn refs, operation;
- idempotency fingerprint/key safe, `status=pending|succeeded|failed|unknown_reconcile`;
- before/after version, canonical result/error code, external receipt/ref safe, timestamps;
- UNIQUE tenant+action/idempotency scope și RLS/grants/retention.

Snapshotul display poate captura fapte verificate la acel moment în result ledger pentru exact replay;
următorul read/mutation rehidratează fresh și nu tratează snapshotul vechi drept truth.

## Pași de implementare

1. Rulează data-readiness sub-planul și oprește orice claim/CTA fără source. Documentează semantica exactă
   a „cart canonic” pentru mediul curent.
2. Definește models/caps și porturile. Separă `Known(value,verified_at,source)` de `Unknown(reason)`;
   evită `None` ambiguu pentru stock/delivery/promo.
3. Alocă migrarea reală și implementează tabelele/checks/RLS/grants. Fiecare query are explicit
   `WHERE business_id=$1`, chiar cu RLS.
4. Implementează facts provider batch pentru toate refs din cart; validatează published, variant relation,
   currency și freshness. Un query/provider call per batch/source, nu per item.
5. Implementează `get_snapshot`: hydrate fresh, calculează toate display strings/totals server-side,
   dar numai din facts known. Mixed/unknown price produce total unknown și checkout omis.
6. Implementează mutate într-o tranzacție scurtă: lock/version check → rehydrate/precondition înainte de
   tx sau revalidate critic în tx → safety/stock policy → mutate → receipt/version. Nu ține conn peste HTTP.
7. Pentru adapter extern, scrie receipt `pending` înainte de call cu key stabil, eliberează DB, apoi
   finalizează/reconciliază. La response loss nu repeta orb mutația.
8. Leagă action consume NX-236 și target turn NX-232 de receipt. Same client turn replayează ViewModelul;
   alt turn nu dublează action.
9. Refactorizează `cart_add_tool` și `checkout_link_tool` să folosească serviciul; adaugă set/remove/clear
   numai dacă semantics sunt complete. Elimină orice `state_patch={cart:...}` nou.
10. Migrează stateul conversației la `cart_ref`; rows legacy se citesc conservator sau sunt invalidate,
    nu importate cu price stale fără revalidare.
11. Expune către NX-240 un `CartSnapshot` display-ready și receipt copy facts, nu raw adapter payload.
12. Adaugă reconciliation worker/runbook, retention/GDPR și alarme pentru pending/unknown receipts.

## Failure/concurrency matrix

| Caz | Comportament obligatoriu |
|---|---|
| două add simultane, aceeași action | un receipt/o singură creștere |
| retry după response loss | același receipt+snapshot; zero a doua mutație |
| expected version stale | conflict + snapshot fresh server-owned, fără merge în FE |
| variantă nu aparține produsului | reject înainte de mutation |
| produs unpublished/contraindicat | reject grounded; cart neschimbat |
| stock 1, quantity 2 | bounded reject/adjust numai conform policy canonică, explicat |
| stock provider timeout/stale | `UNKNOWN`, CTA add/checkout omis; nu presupune in-stock |
| price/list price necunoscut | fără discount/total inventat; checkout blocat dacă suma e necesară |
| promo/voucher expirat/lipsă source | omis; receipt nu promite discount |
| delivery feed absent | fără ETA/promise; eventual notice UNKNOWN |
| rating/review absent | câmpurile omise; nu afectează mutation |
| external call reușește, răspuns se pierde | receipt `unknown_reconcile`; lookup înainte de retry |
| DB commit eșuează după external success | reconciliation leagă external key; nu dublează |
| mixed currency | cart/checkout refuzat sau separat conform policy, nu sumă greșită |
| alt tenant/session folosește cart ref | 404/403 fără leak |
| cart expirat/checked out | error view + cart snapshot policy, nu resurrect silent |

## Codex Attack Plan

1. Trimite același action simultan prin click și retry/tool; caută quantity/receipt dublu.
2. Schimbă price/stock/variant după ViewModel, apoi execută tokenul; trebuie revalidare fresh.
3. Oprește fiecare feed și caută afirmații/CTA pentru stock, delivery, promo sau discount UNKNOWN.
4. Induce external success + response loss + DB failure și verifică reconciliation înainte de retry.
5. Cere cart/receipt cu alt tenant/session și inspectează query-ul pentru `business_id=$1`.
6. Caută `state_patch.*cart`, calcule de total/discount în FE și N+1 pe 10 linii; orice bypass este finding.
