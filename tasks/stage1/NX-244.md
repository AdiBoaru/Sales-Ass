## Outcome verificabil

WebWidgetul v2 randează `WebViewV2.messages[].blocks[]` exact în ordinea primită printr-un registry
finit `block.type → componentă`. Toate valorile comerciale și conversaționale sunt display-ready din
backend: text, preț afișat, discount, rating, status, freshness, criterii, comparație, CTA, greeting,
disclaimer și fallback. Frontendul nu le calculează, nu le deduce și nu le completează.

Orice control conversațional trimite numai `activation.token` neschimbat către controllerul NX-243.
Un link deschide numai `activation.href` deja validat, cu defense-in-depth de schemă/scheme. Widgetul
nu importă și nu mută coșul, wishlistul, catalogul sau memoria client-side.

## Boundary frontend pasiv — regulă executabilă

### Permis

- `switch(block.type)` într-un registry exhaustiv;
- maparea enumurilor allowlisted `tone`, `appearance`, `icon`, `variant` la CSS/componente locale;
- layout responsive, truncation pur vizuală, focus, scroll și expand/collapse;
- escape de text prin React și sanitizare de URL defense-in-depth;
- trimiterea tokenului opac exact sau navigarea la href exact;
- state local pur vizual, de exemplu `expandedBlockId`, fără modificarea faptelor afișate.

### Interzis

- `Intl.NumberFormat`/`Number()`/`Math.round()` pentru date comerciale;
- calcul sau inferență din `price`, `list_price`, `stock`, `rating`, `label`, `product_id`;
- regex/NLP pentru a decide heading, listă, intro, tone, icon, intent sau CTA;
- defaults precum `RON`, „—”, „În stoc”, `/Cart`, greeting/disclaimer/error comercial;
- sortarea/reordonarea/deduplicarea produselor, rows, steps, badges sau actions;
- generarea unui mesaj din label/nume și retrimiterea labelului în loc de token;
- importuri din cart, wishlist, catalog, productContent ori orice tool de recomandare;
- mutații commerce locale sau confirmări fără receipt server;
- HTML, CSS classes, SVG, script ori component names arbitrare din backend.

Frontend pasiv nu înseamnă renderer HTML remote. Backendul alege numai tokenuri semantice finite;
frontendul deține implementarea sigură a componentelor și design systemului.

## Arhitectura componentelor

### Registry finit

```js
const BLOCK_RENDERERS = {
  text: TextBlock,
  product_list: ProductListBlock,
  comparison: ComparisonBlock,
  key_value: KeyValueBlock,
  status_list: StatusListBlock,
  routine: RoutineBlock,
  notice: NoticeBlock,
  memory: MemoryBlock,
  cart_summary: CartSummaryBlock,
  action_row: ActionRowBlock,
};

export function BlockRenderer({ block, onSubmitAction }) {
  const Component = BLOCK_RENDERERS[block.type];
  // NX-242 garantează unionul finit; lipsa componentei este defect de build/contract, nu skip runtime.
  if (!Component) throw new WebViewRendererInvariantError(unregistered_block_type);
  return <Component block={block} onSubmitAction={onSubmitAction} />;
}
```

Registryul nu este extensibil prin nume de componentă primit din rețea. Orice tip nou cere contract,
componentă, test și release coordonat.

### Text

`TextBlock` folosește `block.variant` pentru tag/style allowlisted și redă `block.text` ca text React.
Nu parsează markdown pentru a ghici headings/lists. Dacă designul cere bold/listă, projectorul trebuie
să emită blocuri/spans structurate prevăzute de schema NX-228; nu se reintroduce
`dangerouslySetInnerHTML` ori regex.

### Product list/card

Cardul v2 afișează numai fields display-ready, de exemplu `price.current`, `price.previous`,
`price.discount`, `rating`, badges și labels. Absența unui string înseamnă că elementul nu se afișează.
Nu recalculează dacă reducerea este „reală”, nu derivează procentul și nu folosește un preț raw ca
fallback.

Variantele/nuanțele, dacă sunt în schema finală, trebuie să conțină starea vizuală și acțiunea opacă
server-owned. FE nu dezactivează o opțiune pentru că `stock===0` și nu schimbă prețul local; redă
`disabled/selected/label/tone` și, la activare permisă, trimite tokenul asociat.

### Comparison

Headers, cells, winner/delta labels și missing-value display vin complet din backend. FE păstrează
ordinea. Desktop/mobile pot avea două layouturi CSS ale acelorași date, dar nu schimbă câștigătorul,
nu construiesc rows și nu completează `null` cu text local.

### Action control

Singurele activation types Stage 1:

- `submit`: `<button>` → `onSubmitAction(action.activation.token)` exact;
- `navigate`: `<a>`/router navigation la `action.activation.href` exact, cu target/rel din politica
  locală sigură și scheme allowlisted.

`appearance` alege doar clasa vizuală. Nu există switch pe `checkout`, `book`, `add_to_cart`, produs
sau stoc. Tokenul nu este decodat, concatenat, logat ori pus în DOM attributes în afara handlerului.

### Unknown block

Orice tip necunoscut schemei/hashului negociat este respins de NX-242 și nu ajunge la renderer.
Registryul este exhaustiv pentru hashul acceptat; dacă un build omite o componentă pentru un tip valid,
acesta este `WebViewRendererInvariantError` și activează calea tehnică unavailable pentru întregul view,
nu omiterea blocului, UI parțial ori `JSON.stringify(block)`. Un bloc nou cere rollout coordonat
schema/hash + decoder + registry + teste înainte ca backendul să negocieze acel hash cu acest client.

## Separarea v1/v2 în perioada de canary

- v2 are entry point/component tree propriu și nu importă componentele legacy v1;
- protocolul este ales prin configurație explicită de build/deploy stabilită în NX-249, nu prin
  inspectarea shape-ului unui response;
- bundle-ul v2 trebuie să tree-shake componentele/demo logic v1;
- legacy v1 poate rămâne temporar într-un entry separat pentru rollback, dar nu este permis în chunkul
  activ v2 și se elimină conform NX-249;
- testele v1 nu sunt redenumite drept v2. Fixtures v2 provin din NX-228/NX-240.

## Race și failure matrix obligatorie

| Caz | Comportament obligatoriu | Interzis |
|---|---|---|
| blocks în ordine neobișnuită | aceeași ordine în DOM | reordonare „mai frumoasă” |
| product fără `previous/discount` | omite elementele | calcul din raw price |
| badge label neașteptat, tone valid | culoarea tone explicită | inferență din label |
| tone/appearance/icon invalid | decoderul respinge înainte | fallback semantic ghicit |
| cells cu text „—”/missing display | afișează exact ce vine | completare locală |
| action submit rapid repetată | controllerul NX-243 decide busy | interpretare/dublu handler |
| action token cu caractere speciale | passthrough byte-identic | decode/trim/concatenare |
| navigate URL invalid la defense layer | control inactiv/contract diagnostic | deschidere URL |
| unknown block pe wire | decoderul NX-242 respinge întregul payload | omit/skip/render parțial |
| tip valid în schema acceptată, dar absent din registry | invariant error + technical unavailable pentru view | return `null`/UI parțial |
| empty terminal view | imposibil prin NX-242; error path | fallback comercial local |
| cart action fără NX-237 receipt | backend nu emite succes/FE nu simulează | localStorage mutation |
| re-render în timpul clickului | aceeași action identity | regenerare token/text |
| fixture production preview query | nu se încarcă | sample conversation în prod |

## Metrici și observabilitate

Instrumentation seam, fără conținut din payload:

- `web_view_render_total{schema_major,outcome}`;
- `web_block_render_total{block_type,outcome}`;
- `web_view_render_total{schema_major,outcome=renderer_invariant_error}`; tipul brut nu devine label;
- `web_action_activate_total{activation_type,appearance}`;

reușit.

## Codex Attack Plan

1. Trimite `price.current="1 leu"`, raw hidden price foarte diferit și verifică textul: FE trebuie să
   afișeze exact `1 leu`, fără recalculare.
2. Trimite badge `label="Reducere 99%"`, `tone="neutral"`; culoarea trebuie să rămână neutral.
3. Inversează blockurile text/product/action; DOM trebuie să păstreze ordinea absurdă — backendul este
   ownerul compoziției.
4. Schimbă labelul chipului, păstrează tokenul și click; requestul trebuie să fie byte-identic.
5. Injectează `javascript:` și un unknown block; decoderul trebuie să respingă întregul payload, fără
   render best-effort. Elimină apoi o componentă validă din registry; trebuie invariant error, nu `null`.
6. Caută `Math.round`, `Intl.NumberFormat`, `Number(`, `RON`, `/Cart`, `addToCart`, `wishlist`, regex
   de heading și copy comercial în v2. Orice derivare contextuală este finding.
7. Simulează action cart fără backend receipt; orice toast/succes/localStorage mutation este finding.
8. Deschide production `?preview=1`; sample thread este finding critic de scope/billing/confuzie.
9. Inspectează chunkul v2, nu doar source imports; legacy/business code prezent este finding dacă
   selecția de build promite tree-shaking.
