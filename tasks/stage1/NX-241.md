## Outcome verificabil

Fiecare turn web are un singur deadline monoton end-to-end și bugete explicite pentru queue, retrieval,
model rounds, tool calls, critic/repair, validation, projection și cost. Fiecare operație primește timpul
rămas; timeouturile și retry-urile nu se multiplică. Independent reads sunt batch/parallel, mutation
tools rămân seriale/idempotente, iar profiling/summarizare/rollups rulează după terminal commit.
Sub load sau provider outage, utilizatorul primește în timp bounded un ViewModel final onest, niciodată
spinner infinit, tăcere sau un draft nevalidat.

## Boundary frontend — nenegociabil

Frontendul nu decide timeoutul semantic, nu face retry cu ID nou, nu simulează stadii prin timere și nu
afișează tokeni/drafturi pentru „viteză”. El respectă `poll_after_ms`, statusurile reale și
`composer.enabled`, apoi afișează resultul atomic. Backofful de transport poate fi generic și server-guided;
ce se omite/degradează la deadline și textul aferent sunt exclusiv backend-owned.

## SLO și bugete inițiale

Ținte Stage 1 din ADR, măsurate end-to-end de la accept committed până la terminal result sub loadul
ratificat (nu doar timpul API model):

- POST accept: p90 ≤ 300ms, p99 ≤ 800ms;
- fapt simplu: 1,5–3s, cu p90 ≤ 3s;
- recomandare normală: 3–6s, cu p90 ≤ 6s;
- comparație/mixed complex: 6–10s, cu p90 ≤ 10s;
- global p90 < 12s; hard execution deadline provisional 15s pentru a produce success ori fallback terminal;
- zero DB connections ținute peste LLM/HTTP/backoff/SSE și zero turnuri active după deadline+grace.

Valorile devin config pe clase/policy, nu constante presărate. Nu sacrifica factualitatea/hard constraints
ca să atingi SLO. Ordinea optimizării: elimină relay/apeluri inutile, batch/parallel safe, reduce payload,
prompt caching; abia apoi evaluează model/reasoning changes blind. Runtime modelul nu se schimbă în acest
card fără gate de calitate NX-246.

### `TurnDeadline`

- creat din `deadline_at` ledger și clock monoton la claim;
- `remaining_ms(stage_reserve=...)`, `timeout_for(operation_cap)`, `checkpoint(stage)` și cancel signal;
- queue wait și reclaim attempts consumă același deadline; retry nu îl resetează;
- fiecare LLM/embed/rerank/tool/DB/provider primește `min(cap, remaining-reserve)`;
- dacă `Retry-After`+minimum useful budget nu încape, nu doarme/retry; degradează conform policy;
- rezervează timp pentru validator, safe fallback și terminal DB commit.

### `TurnExecutionBudget`

Config versionat per turn class, cu minimum:

- max total/model/retrieval/tools/validation milliseconds și token/cost ceilings;
- max MainBrain rounds, parallel read tools, serial mutation tools, critic calls și repair calls (repair ≤1);
- max tool results/bytes/evidence items/query/provider calls;
- priority `required|optional`; optional work nu consumă rezerva de terminal commit;
- exhaustion reason codes și fallback/no-results mapping.

Modelul nu poate cere mai mult budget prin output. ToolExecutor rezervă/consumă atomic; calls simultane nu
depășesc plafonul prin race. Mutation calls nu sunt lansate speculative sau în paralel.

## Failure matrix

| Caz | Comportament obligatoriu |
|---|---|
| model call consumă aproape tot deadlineul | fără retry/critic; validator+fallback+commit au rezervă |
| 429 cu Retry-After peste remaining | nu așteaptă; degradează terminal |
| embed timeout | lexical/current fallback cu degradation; hard gates păstrate |
| reranker timeout | ordering deterministic fallback; rejected mask păstrat |
| read tools independente | pot rula paralel în cap; results ordered determinist |
| mutation+read tools | mutation serială, după precondiții; fără speculation |
| tool storm cerut de model | budget reject typed; brain finalizează/fallback |
| query/provider result oversized | truncare bounded înainte de prompt, cu coverage metadata |
| queue wait depășește deadline | terminal busy/timeout ViewModel, nu începe lucru inutil |
| worker reclaim | deadline original, nu încă 15s |
| client/SSE disconnect | execuția urmează durable policy; result recuperabil, fără conn leak |
| aftercare timeout/backlog | result rămâne terminal; aftercare retry/drop conform priority |
| projector/commit aproape de cutoff | rezerva dedicată permite error ViewModel commit |
| budget config invalid | startup fail-fast ori safe defaults versionate, nu unlimited |

## Rollout și rollback

Începe observe-only cu deadline enforcement OFF, apoi enforce pe tenant demo cu budgets conservative.
Activează pe turn classes separat: exact/read-only, recommendation, complex, mutation. Stable bucketing și
budget version sunt capturate la accept. Canary cere simultan latency SLO și quality gates NX-246/247;
nu rampa pe latency singură. Rollback dezactivează optimizările riscante/parallelism, dar păstrează un
hard total deadline sigur; nu revine la retry nelimitat/90s și nu pierde turnurile active.

## Definition of Done

- [ ] Există un singur deadline end-to-end, păstrat prin queue/reclaim și propagat tuturor operațiilor.
- [ ] Timeouturile/retry-urile nu se multiplică; Retry-After respectă remaining+reserve.
- [ ] Model/tool/token/cost/query/provider budgets sunt versionate și enforce atomic.
- [ ] Read-only independent work este batch/parallel; mutations sunt seriale/idempotente.
- [ ] Validator/fallback/commit au rezervă și fiecare turn ajunge terminal non-empty.
- [ ] Aftercare nu întârzie resultul și nu ține composer/DB connection.
- [ ] Zero connections peste LLM/HTTP/backoff/SSE și zero N+1 peste buget.
- [ ] SLO-urile ratificate sunt verzi sub load sau există verdict NO-GO fără ramp.
- [ ] Quality/factual/hard-constraint gates nu regresează pentru latency.
- [ ] Frontendul nu simulează progres/timeout/fallback; manual drive și gate complet verzi.

## Codex Attack Plan

1. Setează fiecare provider la timeout aproape de cutoff și numără retry/calls; caută depășirea deadlineului.
2. Returnează Retry-After mare și tool storm; verifică rezerva de fallback+commit și terminal P6.
3. Rulează read+mutation tools simultan și caută side effect speculativ/dublu.
4. Blochează aftercare și analytics; resultul/composer recovery trebuie să rămână rapid.
5. Rulează burst peste pool, inspectează db_hold și fairness între tenanți.
6. Compară răspunsurile înainte/după optimizare blind; orice claim lipsă/fals ori hard relaxation este finding.
