## Outcome verificabil

WebWidgetul v2 poate fi folosit complet cu tastatura și screen readerul, se revarsă corect la 320px și
400% zoom și nu permite introducerea ori activarea unei a doua ture cât timp backendul raportează un
turn neterminal. Composerul, microfonul, chipsurile, feedbackul, variantele și orice control cu
`activation.type="submit"` sunt realmente inactive, nu doar ignorate în handler. Close și controalele
pur vizuale rămân utilizabile; navigarea simplă urmează politica explicită de produs.

Busy/progress/completion/failure sunt anunțate din strings server-owned. Frontendul nu inventează
„Analizez”, „Caut”, „Am găsit”, „Mai încearcă” sau alte stări conversaționale.

## Existing state și probleme confirmate

- inputul din `ChatWidget.jsx` nu are `disabled`/`readOnly` când `sending`; userul poate scrie, dar
  submitul este apoi ignorat;
- chipsurile din `ChatMessage.jsx` nu primesc busy și arată active în timpul requestului;
- `ChatProductCard`, feedback, New chat și alte acțiuni nu au o politică single-flight comună;
- butoanele folosesc frecvent `title`, fără `aria-label` stabil;
- panelul nu are semantică clară de dialog, focus management ori return-to-trigger;
- mesajele/progresul nu au un live-region controlat; un răspuns bogat poate fi citit haotic;
- feedbackul local nu comunică status accesibil și nu ajunge la backend;
- microfonul Web Speech poate rămâne într-o stare concurentă cu submit/unmount;
- index keys și conținut dinamic pot destabiliza focusul;
- nu există gate Axe/keyboard/reduced-motion/zoom pentru widget.

## Boundary frontend pasiv aplicată accesibilității

Accesibilitatea este logică de prezentare permisă. Totuși:

- FE poate decide focus, tab order, `aria-live`, `aria-busy`, role, reduced motion și layout;
- FE poate dezactiva un control pentru că state machine spune `isBusy` sau ViewModel spune `disabled`;
- FE nu poate dezactiva/activa după stoc, preț, produs, confidence ori textul labelului;
- FE nu compune aria-label din numele/prețul produsului dacă backendul trebuia să ofere label complet;
- FE nu inventează announcement/progress/error copy; redă `a11y_label`/`announcement` primit;
- FE nu schimbă labelul într-un mesaj și nu creează retry comercial; folosește action tokenul;
- FE nu interpretează de ce turnul este failed ori retryable din text. Urmează fields contractuale.

## Comportament single-flight obligatoriu

### Formula unică pentru controale creatoare de turn

```js
const turnControlsDisabled = controller.isBusy || !view.composer.enabled;
```

Formula este tehnică; nu consultă products/memory/status. Toate controalele care ajung la
`submitText` sau `submitAction` consumă aceeași valoare:

- input text (`disabled`, nu doar `readOnly`, conform cerinței „nu poți scrie”);
- send;
- mic/dictation;
- initial suggestions/chips;
- quick actions, feedback, variant selection și „mai multe”, dacă trimit action token;
- retry/new-chat dacă ar crea o tură nouă;
- orice shortcut keyboard care cheamă submit.

Controale care nu creează turn și pot rămâne active:

- close/minimize;
- expand/collapse pur vizual;
- scroll;
- link `navigate`, numai conform deciziei DoR;
- copy/select text.

Guardul din NX-243 rămâne obligatoriu chiar dacă DOM este disabled. UI disabled singur nu este o
garanție împotriva eventurilor programatice.

### Unlock

- `accepted`, `working`, reconnect și `recovering` păstrează controalele inactive;
- timeout HTTP nu deblochează;
- SSE disconnect nu deblochează;
- numai `completed|failed|cancelled` valid sau reject dovedit înainte de accept poate conduce la
  `ready`, iar `view.composer.enabled` trebuie de asemenea să permită;
- aplică mai întâi ViewModelul terminal, apoi unlock; evită fereastra în care userul trimite înainte
  ca referințele conversației să fie actualizate;
- New chat este disabled în busy; resetul nu poate concura cu rezultatul vechi.

### IME, paste și speech

- Enter în timpul `compositionstart…compositionend` nu trimite;
- Shift+Enter urmează comportamentul explicit al composerului (dacă input multiline); nu se ghicește;
- paste/drag/drop nu ocolesc `disabled`;
- dacă speech recognition rulează când începe submitul, este oprit și listener-ele sunt curățate;
- un transcript speech sosit târziu nu modifică inputul disabled;
- mic absent/unsupported nu lasă un control mort.

## Semantica dialogului și focusului

### Launcher

- `<button type="button">`, nume accesibil primit din bootstrap ViewModel;
- `aria-haspopup="dialog"`, `aria-expanded`, `aria-controls` cu ID stabil;
- focus vizibil și target minim 44×44 CSS px;
- la închidere, focusul revine launcherului care a deschis widgetul, dacă încă există.

### Panel mobil modal

- `role="dialog"`, `aria-modal="true"`, `aria-labelledby`, `aria-describedby`;
- background inert/indisponibil screen readerului cât modalul este deschis;
- focus trap robust, Escape închide, focus inițial pe titlu/composer conform stării;
- close rămâne accesibil chiar în busy;
- body scroll lock cu cleanup la unmount/route/error.

### Panel desktop non-modal

- `role="dialog"` cu title/description, fără `aria-modal=true`;
- fără focus trap și fără background inert; userul poate inspecta pagina în paralel;
- Escape/close și return-to-trigger funcționează;
- focusul nu este furat la fiecare progress/re-render.

Se poate folosi un primitive matur precum `@radix-ui/react-dialog` dacă suportă exact cele două moduri,
designul și bundle budgetul. Dacă se adaugă, PR-ul documentează versiunea, licența și bundle delta.
Dacă se implementează manual, testele focus/inert/portal/cleanup de mai jos sunt obligatorii.

## Mesaje și live regions

- containerul transcriptului: `role="log"`, `aria-live="polite"`, `aria-relevant="additions"` și
  `aria-busy` din controller;
- nu forța screen readerul să recitească toate cardurile la fiecare revision;
- folosește o regiune live separată, visually hidden, pentru `view.a11y.announcement` server-owned;
- progresul real: `role="status"`, text/a11y label primit de la backend, fără timer/copiere locală;
- erorile terminale: notice block + announcement server-owned; nu folosi automat `role="alert"`
  pentru orice reconnect tranzitoriu;
- IDs/key-urile vin din `message.id/block.id/action.id`, nu index, pentru focus stabil;
- după completion nu autofocus composerul dacă userul a mutat focusul în afara widgetului; dacă focusul
  era în controlul submit care a devenit disabled, mută-l controlat în status și apoi oferă composerul.

## Semantica componentelor bogate

- `ProductList`: listă semantică; imaginea folosește `image.alt` primit. `alt=""` numai când schema
  marchează explicit imaginea decorativă;
- `Comparison`: `<table>` cu caption, `<th scope="col|row">` și cells în ordinea backend. Layoutul
  mobil poate avea reprezentare alternativă numai dacă duplicatul inaccesibil este ascuns corect;
- `KeyValue`: `<dl><dt><dd>`;
- `Routine`: `<ol>`;
- `StatusList/Memory/ProductList`: `<ul>` unde se potrivește semantic;
- `ActionRow`: fiecare control are label complet și state `disabled/aria-disabled` coerent;
- iconurile decorative au `aria-hidden="true"`; un icon fără text cere label server-owned;
- loading skeleton/spinner nu expune animații fără nume și respectă `prefers-reduced-motion`.

## Responsive, zoom și motion

- fără horizontal scroll al întregii pagini la 320px și 400% zoom;
- comparison poate avea container propriu sau variantă verticală, fără pierdere de cells/actions;
- safe-area insets pe mobile și tastatura virtuală nu ascund composerul/close;
- targeturile interactive au minimum 44×44 unde designul permite; spațierea previne tap accidental;
- focus ring are contrast ≥3:1 față de culorile adiacente;
- text/controale respectă WCAG 2.2 AA contrast și nu depind numai de culoare;
- `prefers-reduced-motion: reduce` oprește slide/spinner nonesențial; statusul rămâne textual;
- browser zoom/reflow păstrează ordinea DOM și nu dublează content pentru screen reader.

## Race și failure matrix obligatorie

| Scenariu | UX obligatoriu | A11y/focus obligatoriu |
|---|---|---|
| submit text | toate turn controls inactive imediat | focus mutat sigur din input disabled/status anunțat |
| double click/Enter | un singur submit | fără două announcements |
| IME Enter | nu trimite până la composition end | textul compus păstrat |
| mic activ + submit | mic oprit/cleanup | state ascultare anunțat corect |
| accepted/working | input nu poate primi text | `aria-busy=true`, progress server-owned |
| HTTP timeout | rămâne busy/recovering | nu anunță fals failure/completion |
| SSE reconnect | rămâne busy | update status politicos, fără focus steal |
| completed | ViewModel aplicat, apoi unlock | announcement o dată; focus nu este furat abuziv |
| failed terminal | respectă `composer.enabled` | notice/announcement server-owned |
| New chat în busy | disabled | nu este tabbable/clickable ca activ |
| submit action în busy | disabled/guard | state perceput, nu doar no-op |
| navigate în busy | conform deciziei DoR | link semantic și focus predictibil |
| close în busy | permis | focus revine launcher; turn continuă server |
| reopen în busy | snapshot/progress curent | focus/status corect, fără turn nou |
| mobile→desktop resize | modalitate actualizată fără leak | inert/trap eliminate/adăugate coerent |
| result rerender | stable keys | focus nu sare din control pur vizual |
| image fail | layout stabil | alt server-owned rămâne disponibil |

## Test Cases

### Automated accessibility

- `jest-axe` pe welcome, busy, recommendation, comparison, routine, error și no-results: zero
  violations serious/critical;
- accessible-name assertions pentru launcher, close, composer, send, mic, New chat și toate actions;
- role assertions pentru dialog/log/status/table/list/dl/ol;
- iconurile decorative sunt ascunse; images respectă `alt/decorative` din contract;
- contrast/reduced motion sunt verificate prin token tests și browser gate NX-247.

### Keyboard/focus

- Tab/Shift+Tab în mobile modal rămân în dialog; desktop non-modal nu este prins;
- Escape închide și returnează focus;
- Enter trimite o dată, Shift+Enter/IME conform composer spec;
- focus nu intră în controls disabled;
- close/expand/navigate rămân accesibile după politica stabilită;
- completion/reconnect/re-render nu mută focusul necerut.

### Single-flight

- fiecare control `submit` este disabled în `submitting|waiting|recovering`;
- eveniment programatic în disabled este oprit și de controllerul NX-243;
- timeout/SSE loss nu deblochează;
- terminal apply precedă unlock;
- mic late result și double-click nu pot modifica draftul ori crea a doua tură.

### Responsive/manual-support

- viewport 320×568, 360×800, 390×844, 452px panel și desktop;
- zoom 200%/400%, text spacing WCAG și virtual keyboard;
- comparison maxim, long labels, 6 cards, maximum actions;
- `prefers-reduced-motion`, forced colors/high contrast unde browserul permite.

## Codex Attack Plan

1. Focusează inputul și pornește submit; încearcă `userEvent.type` în toate stările neterminale. Orice
   modificare a valorii este finding.
2. Declanșează click programatic pe chip disabled; controllerul nu trebuie apelat.
3. Produce timeout/SSE disconnect și verifică `disabled`; unlock prematur este finding critic.
4. Apasă Enter în timpul composition IME; un POST este finding.
5. Începe speech, submit, apoi livrează transcript târziu; draftul nu trebuie mutat.
6. Deschide mobile modal, resize desktop, închide; caută body inert/scroll-lock/focus trap rămas.
7. Rulează Axe pe fiecare fixture și inspectează manual Accessibility Tree pentru comparison.
8. Schimbă `a11y_label` backend fixture cu sentinel; FE trebuie să-l redea exact, nu să compună altul.
9. Navighează 20 cicluri/open-close; listeners, portaluri și focus sentinels nu trebuie să se multiplice.
