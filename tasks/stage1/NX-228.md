## Outcome verificabil

Există un contract Pydantic și JSON Schema versionat în care backendul livrează un ViewModel
display-ready. Frontendul poate afișa răspunsul folosind numai `switch(block.type)` și tokenuri
vizuale allowlisted; nu calculează și nu interpretează nicio regulă comercială sau conversațională.
V1 rămâne separat și neschimbat până la cutoverul NX-249.

## Boundary frontend — nenegociabil

Backendul deține textul, localizarea, ordinea blocurilor, prețurile afișate, discountul, stocul,
freshness, rankingul, criteriile, memory copy, comparația, CTA-urile și toate fallbackurile.
Frontendul nu primește instrucțiuni de calcul. El validează schema, mapează tokenuri semantice pe
componente/CSS, randează și retransmite `action_token` exact. Fără raw HTML, class names, SVG sau JS
în payload.

## Contract obligatoriu

### Request

```json
{
  "schema_version": "web-turn.v2",
  "client_turn_id": "uuid-required",
  "input": {"type": "text", "text": "Compară-l cu ceva mai ieftin"},
  "context": {
    "surface": "product",
    "product_id": "opaque-id",
    "variant_id": null,
    "category_id": null,
    "cart_ref": "opaque-versioned-ref",
    "locale": "ro-RO"
  },
  "id_token": "opaque-optional"
}
```

`input` este union exclusiv `text` sau `action`. Varianta action conține numai
`{"type":"action","action_token":"opaque"}`. `client_turn_id` este obligatoriu. Browserul nu
trimite `business_id`, preț, stoc, nume, badge, total, constraints sau conversation state.

### Blocuri Stage 1

Union discriminat, cu `extra="forbid"` pe fiecare variantă:

- `text`: text deja segmentat; `variant=lead|body|caption|disclosure`;
- `product_list`: itemuri display-ready, variante și acțiuni deja decise;
- `comparison`: headers și cells gata localizate; FE nu calculează winner/delta/preț;
- `key_value`: rows label/value gata afișabile;
- `status_list`: label/detail/tone/icon/freshness text furnizate de backend;
- `routine`: pași ordonați și copy complet;
- `notice`: `info|success|warning|error`, inclusiv no-results/fallback/recovery;
- `memory`: snapshot display-ready al criteriilor active, nu istoric append-only;
- `cart_summary`: snapshot server-owned, numai după NX-237;
- `action_row`: acțiuni `submit` opace sau `navigate` validate;
- `spacer/divider` numai dacă designul existent chiar are nevoie; fără layout arbitrar.

Tokenuri allowlisted:

- `tone`: `neutral|info|success|warning|danger`;
- `appearance`: `primary|secondary|chip|link|danger`;
- `icon`: enum documentat; niciodată SVG/raw URL executabil;
- scheme URL: `https` și rute relative explicit allowlisted; fără `javascript:`, `data:`, `file:`.

### Chrome și accessibility copy server-owned

Contractul include explicit, localizat și bounded: launcher label, dialog title/description, composer
label/placeholder, send label, close label, new-chat label și announcements pentru toate statusurile
wire. Backendul/NX-240 proiectează valorile; NX-245 le consumă exact pentru accessible names și live
region. Frontendul poate alege role/focus/aria-live politeness ca logică UI, dar nu inventează,
traduce, concatenează sau înlocuiește copy-ul. Câmp lipsă/empty într-un view care expune controlul ori
statusul este contract invalid și produce numai fallbackul tehnic cunoscut, nu un label local.

### Lifecycle/error

- statusul wire canonic este exact `accepted|working|validating|completed|failed|cancelled`;
- stările neterminale pot avea un `progress_view` server-owned, fără CoT;
- toate terminalele `completed|failed|cancelled` au întotdeauna minimum un bloc randabil;
- error envelope are `error.code` stabil, `retryable`, `retry_action` opțional;
- folosește `turn.status`, nu top-level `status`, deoarece v1 folosește `status` pentru stoc.

### Versionare

- major necunoscut: clientul refuză contractul și afișează numai eroarea tehnică locală minimă;
- unionul de blocuri este finit și strict (`extra="forbid"`): orice `block.type` necunoscut sau
  câmp extra produce reject pentru întregul payload; nu există skip/omit best-effort;
- backendul publică JSON Schema cu hash stabil și nu trimite unei capabilități client un schema hash
  neacceptat. Un rollout minor/aditiv cere capability/schema-hash negotiation înainte de trafic;
- fallbackul terminal este întotdeauna un bloc cunoscut din schema negociată;
- v1 și v2 au endpointuri/randori separați; fără aliasuri care ghicesc câmpuri.

## Failure matrix obligatorie

| Caz | Rezultat |
|---|---|
| `client_turn_id` lipsă/invalid | 422 tipizat, fără pipeline |
| text și action simultan | 422 |
| bloc fără câmp obligatoriu | respins înainte de persist/livrare |
| URL cu schemă interzisă | bloc/action invalid; fallback terminal |
| text/array peste limită | validare fail-closed, event low-cardinality |
| major necunoscut | contract error tehnic, fără interpretare best-effort |
| orice `block.type` necunoscut/câmp extra | întregul payload este respins; serverul livrează numai fallback cunoscut pe schema negociată |
| schema hash/capability neacceptat | serverul nu livrează acel schema; contract error tehnic fără fallback v1 magic |
| `completed|failed|cancelled` fără blocuri | invalid; P6 fallback cunoscut server-owned |
| chrome/a11y label sau announcement obligatoriu lipsă | contract invalid; FE nu compune text local |

## Codex Attack Plan

1. Construiește `completed` cu `messages=[]`/`blocks=[]`; trebuie respins.
2. Injectează `javascript:`/raw HTML/className într-un bloc; nu trebuie să devină randabil.
3. Repetă terminal-empty pentru `failed` și `cancelled`; ambele trebuie respinse.
4. Injectează un block type/câmp extra necunoscut într-un payload altfel valid; orice omit/render
   parțial în loc de reject este finding.
5. Șterge fiecare label/announcement și încearcă să găsești text inventat în FE.
6. Caută orice instrucțiune de tip „frontendul calculează/decide/derivează”. Finding confirmat dacă există.
7. Rulează fixtures v1 și verifică zero schimbări accidentale.
