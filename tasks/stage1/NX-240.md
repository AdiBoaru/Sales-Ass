## Outcome verificabil

`AnswerPlanV2` nu ajunge direct în browser. Un `GroundingGuard` determinist validează fiecare claim,
produs, comparație, acțiune și state disclosure față de un `EvidenceBundle` canonic; apoi un projector
pur produce `web-view.v2` complet display-ready. Preț/list price/discount, monedă, stoc, variantă,
rating/review-uri, livrare, promo/voucher, badges, motive, URL-uri, cart totals, labels și error copy sunt
decise și formatate în backend. Dacă source/freshness lipsește, câmpul este `UNKNOWN`/omis și CTA-ul
dependent dispare. Frontendul face numai validare structurală, component mapping și randare.

## Existing state și dovezi reproductibile

- `src/channels/web/render.py:render_web` v1 emite `{content,products,suggestions,offer,comparison}` și
  mapează chips la strings, pierzând `Chip.payload`.
- v1 produce unele fields (`image`, `url`, `rating`, `review_count`, `list_price`, `variants`), dar
  frontendul real are și fixture-only `title/understanding/status/confidence/routine/noResults/criteria/
  highlights/meta/score` fără owner/contract comun.
- `docs/FRONTEND-CONTRACT-IZI.md` cere frontendului să derive discount/stock/currency în unele cazuri;
  aceasta contrazice boundary-ul Stage 1 și trebuie superseded numai pentru v2, nu schimbat in-place.
- `src/agent/validator.py`, `pricing.py`, `answer_plan_guard.py` verifică deja clase de claims, dar nu există
  un singur gate care validează plan→evidence→fiecare bloc ViewModel.
- Commerce/catalog pot avea preț/rating/variant fields, însă stock, delivery/promo și `verified_at` nu au
  coverage garantată; UI fixtures nu sunt sursă de adevăr.

## Boundary frontend — nenegociabil

Frontendul nu calculează, compară sau interpretează nimic comercial/conversațional. Nu derivează
discount din două prețuri, stock din `0/null`, availability din variantă, rating text, delivery ETA,
winner, criteria, confidence, reason, no-results, cart total sau voucher eligibility. Nu inventează copy,
nu cade pe fixtures și nu convertește unknown în „indisponibil”. Primește strings/tones/actions finite și
le randează în ordinea dată. Nu acceptă HTML/CSS/JS/SVG remote.

## Contract de grounding

### `EvidenceBundle`

Bundle-ul este immutable, bounded și indexat prin IDs, cu provenance per fact:

- product identity/title/description attributes și published status;
- price Decimal, list price, currency, valid interval și `verified_at`;
- variant relation/attributes și availability tri-state/freshness;
- rating, review_count, review_summary/pros/cons din aggregate/content aprobat;
- delivery promise/interval/source/verified_at;
- promotion/voucher rule, eligibility, validity și source;
- URLs/images allowlisted și content provenance;
- constraint verdicts, evidence chunks/claim provenance și retrieval provider/version;
- cart snapshot/receipt facts când NX-237 este disponibil.

`Known`, `Unknown(reason)` și `Stale(age,policy)` sunt distincte. Lipsa unui câmp nu este `false/0`.

### `GroundingGuard`

- fiecare claim numeric/comercial/link/stock/delivery/promo/review are evidence ID și fact typed;
- orice number/price/percentage/stock assertion în proză este cross-check-uit cu facts; mismatch → reject;
- motivele recomandării leagă `need_key + product_fact/evidence`, nu adjective generice;
- hard constraint MISMATCH blochează produsul; UNKNOWN este disclosure/refinement, nu match declarat;
- comparison cells și winner/delta sunt calculate din facts compatibile; missing cells rămân explicit unknown;
- action args referă numai produse/variante din bundle și respectă availability/receipt policy;
- stale fact peste SLA este omis/etichetat; modelul nu poate prelungi freshness;
- validatorul produce reason codes, niciodată corectare factuală inventată.

### `WebViewProjectorV2`

Funcție pură, fără DB/HTTP/LLM/clock implicit:

```text
project(answer_plan, evidence_bundle, state_snapshot, locale, issued_actions, now)
  -> WebViewV2
```

Toate datele sunt pregătite înainte. Projectorul folosește `Decimal`, reguli locale și, dacă repo-ul nu
are deja utilitar suficient, o bibliotecă matură precum Babel pentru currency/number/plural formatting,
pin-uită și testată; nu folosește float/string concat pentru bani. Discountul se emite numai când
`list_price > current`, aceeași monedă și ambele facts sunt fresh/canonice.

Blocuri minime complete: text, product_list, comparison, key_value, status_list, routine, notice,
memory, cart_summary condițional, action_row. Fiecare item are strings display-ready, `view_id` stabil în
turn, provenance internă (nu neapărat expusă), actions deja emise și fallback/accessibility copy.

Projectorul populează explicit și contractul `chrome`/a11y-copy definit de NX-228: titlul asistentului,
labelurile server-owned pentru open/close/send/retry, labelul și placeholderul composerului, plus
anunțurile localizate pentru `accepted|working|validating|completed|failed|cancelled`. Frontendul decide
numai mecanica accesibilă (roluri, focus, `aria-live`, `aria-busy`, reduced motion) și leagă exact
strings primite; nu inventează status/error/recovery copy și nu transformă a11y într-un canal semantic
paralel. Niciun câmp chrome nu conține HTML, selector CSS sau instrucțiuni arbitrare.

## Diferența de date față de experiențe precum iZi

Paritatea vizuală/semantică nu autorizează date inexistente:

| Câmp dorit | Source obligatoriu | Când source lipsește/stale |
|---|---|---|
| price/list price/discount | catalog/pricing adapter canonic + verified_at | omit price/discount dependent copy/CTA |
| stock/variant availability | inventory per variant | `UNKNOWN`; nu „în stoc”, add/checkout omis |
| rating/count/summary | aggregate/review content aprobat | omit rating/summary; nu zero stele fictiv |
| delivery promise | fulfillment/delivery adapter | omit ETA; notice numai dacă util |
| promo/voucher | promotion engine/regulă validă | omit complet; fără „cod posibil” |
| comparison/reason | evidence + active need | cell/reason absent sau unknown onest |

iZi este benchmark comportamental pentru claritate/naturalețe/utilitate, nu contract de payload și nu
sursă de copy/date. Nu copia texte, branding, flows proprietare sau claims de pe eMAG.

## Failure matrix

| Caz | Comportament obligatoriu |
|---|---|
| plan citează preț diferit de evidence | reject/repair/fallback; claim fals nu este proiectat |
| list price ≤ current ori currency diferită | previous/discount omise |
| stock/variant UNKNOWN | label onest/omis și cart CTA omis |
| rating fără count/source | rating block omis conform policy, nu „0 review-uri” |
| review summary neaprobat/stale | omis; motivul folosește alt evidence sau dispare |
| delivery adapter absent | ETA/promise omis, fără calcul FE |
| promo/voucher fără eligibility/source | omis complet |
| hard constraint MISMATCH în plan | produs blocat și no-results/alternative safe |
| comparison fact missing | cell unknown/— server-owned; fără winner fals |
| action pentru produs neemis/stale | action guard reject; CTA omis/error view |
| URL `javascript:`/host interzis | action/item invalid; terminal safe view |
| formatter locale eșuează | safe localized fallback, nu raw float/500 |
| projector primește plan invalid/gol | refuz + notice terminal P6 |
| DB/provider monkeypatch apelat în projector | test hard-fail |
| retry result după facts schimbate | replay exact persisted view, nu reprojectare |

## Rollout și rollback

Rulează projectorul shadow și compară structure/grounding cu v1 fără a livra v2. Activează pe tenant demo
după data-readiness și fixtures, apoi doar împreună cu decoderul strict NX-242/renderer NX-244. Pairwise
