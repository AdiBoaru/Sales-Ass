# NX-320 — modelul alege filtrele căutării fără să gândească: bucla cu unelte pe Responses API

**Stare:** felia 1 LIVRATĂ (măsurare, zero schimbare live); felia 2 așteaptă verdictul replay-ului · **Prioritate:** P1 · **Wave:** I
**Owner:** S · **Faza:** P1 · **Branch:** `feat/NX-320-responses-tool-loop` · **Complexitate:** L · **Estimare:** 7h, spart în 2 felii [PROPUNERE]
**Repo țintă:** `Sales Ass` · **Tip:** adaptor LLM + măsurătoare · **Migrare:** niciuna
**Flag:** `LLM_TOOL_LOOP_RESPONSES_ENABLED` (implicit **OFF**, byte-identic) + `LLM_REASONING_EFFORT_TOOLS` (implicit `low`, inert cu flagul stins)
**Găsit prin:** review-ul GPT al promptului (2026-09-24) + replay-ul NX-312 felia 5 + evenimentele `guessed_filter_probe`.

## Goal

Singurul apel din tur care decide **ce se caută** (raft, nevoi, preț maxim, sortare) rulează azi
**fără niciun raționament**. Nu e o setare de-a noastră: pe `chat.completions`, `gpt-6-luna` acceptă
function tools doar cu `reasoning_effort=none`, iar `llm._sampling` îl forțează explicit
([llm.py:584](../../src/agent/llm.py#L584)). Taskul mută bucla cu unelte a căii v1
(`LLMClient.run_tool_loop`) pe `/v1/responses`, unde raționamentul și uneltele pot coexista, și
decide pe MĂSURĂTOARE (D15) dacă `reasoning.effort=low` alege argumente mai bune decât `none`, la ce
cost de latență. Adaptorul rămâne singurul loc care vorbește OpenAI.

## Business Context

Aproape toate defectele de calitate din ultimele două săptămâni au fost argumente greșite alese în
apelul ăsta: raftul de pensule la mănușa de autobronzant (NX-305), raftul „Fata" (machiaj) la o
cremă de hidratare (NX-313), un `price_max` de 29,99 dus dintr-un «mai ieftin» anterior (NX-319),
numele de raft în loc de cheie (`cd98a513`). Fiecare a primit o poartă de cod DUPĂ, dar porțile
repară doar clasele pe care le-am văzut deja. Un produs greșit pe primul card e o vânzare pierdută,
iar validatorul nu-l prinde (e o poartă de ADEVĂR, nu de POTRIVIRE).

## Forma măsurată

`analytics_events`, `sole-ro`, de la NX-313 (2026-09-23) încoace:

```
guessed_filter_probe:   11 ture   (tura în care modelul a trimis un filtru pe care clientul nu l-a rostit)
  category_guessed:     10 / 11   raftul e ghicit aproape mereu
  verdict=contradicted:  3 / 11   raftul ghicit contrazice cererea → salvat de NX-313
  verdict=kept, greșit:  ≥1       8d0485c2 «Caut ceva pentru calmare» → BB cream și pudre (raft de machiaj)
```

Latența rundei de tool-calling azi (`llm_usage.per_call`, shape `tools`): **p50 2,2 s, p90 4,0 s**.

Referință de cost al raționamentului pe `gpt-6-luna`, din replay-ul apelului de compunere (NX-312
felia 5, 30 de ture): `none` 5,2 s → `low` 8,5 s p50, **~315 tokeni de raționament** p50. Pe
bucla cu unelte, cu un prompt mai scurt, e de așteptat un adaos de ordinul 1-3 s pe rundă. Asta se
MĂSOARĂ în felia 1, nu se presupune.

## Technical Description

### Ce se schimbă pe sârmă

| | `chat.completions` (azi) | `/v1/responses` (flag ON) |
|---|---|---|
| system | `messages[0].role=system` | `instructions` |
| mesaje | `messages` | `input` (listă de items) |
| unealtă | `{"type":"function","function":{name,parameters,strict}}` | `{"type":"function",name,parameters,strict}` (**plat**) |
| cererea modelului | `message.tool_calls[].id` | item `function_call` cu `call_id` |
| rezultatul uneltei | `{"role":"tool","tool_call_id",...}` | item `{"type":"function_call_output","call_id","output"}` |
| raționament | interzis cu tools | `reasoning={"effort": "low"}` |
| plafon output | `max_completion_tokens` | `max_output_tokens` |
| schemă strictă | `response_format` | `text.format` |
| usage | `prompt_tokens`, `prompt_tokens_details.cached_tokens` | `input_tokens`, `input_tokens_details.cached_tokens`, `output_tokens_details.reasoning_tokens` |

**Raționamentul trebuie retrimis între runde.** Pe Responses, itemii de `reasoning` produși în runda 1
trebuie să însoțească `function_call_output` în runda 2, altfel modelul pierde ce a gândit când a ales
unealta. Fără stare pe server (`store=false`, fiindcă nu vrem conversațiile clienților reținute la
furnizor), asta cere `include=["reasoning.encrypted_content"]` și reintroducerea itemilor ca atare în
`input`. `previous_response_id` e varianta cu stare la furnizor și se EXCLUDE (P12: PII-ul trăiește
într-un singur loc).

### Forma în cod (un singur seam)

```python
# src/agent/llm.py
async def run_tool_loop(self, system, user, tools, execute, *, max_steps=3, model=None,
                        stop_after_tools=None) -> str:
    if _responses_tool_loop_enabled():                        # flag + profil de model
        return await self._run_tool_loop_responses(
            system, user, tools, execute, max_steps=max_steps, model=model,
            stop_after_tools=stop_after_tools,
        )
    ...                                                        # corpul de azi, NEATINS (byte-identic)

async def _run_tool_loop_responses(...):
    items: list[dict] = [{"role": "user", "content": user}]
    for _ in range(max_steps):
        if not _round_admitted():
            break
        resp = await self._respond(model=mdl, instructions=system, input=items,
                                   tools=_flat_tools(tools), reasoning_effort=effort_tools)
        calls = [o for o in resp.output if o.type == "function_call"]
        if not calls:
            return resp.output_text.strip()
        items += [o.model_dump() for o in resp.output]         # reasoning + function_call, IN ORDINE
        contents = await _run_tool_calls(execute, _as_tool_calls(calls))   # ACEEAȘI execuție
        items += [{"type": "function_call_output", "call_id": c.call_id, "output": out}
                  for c, out in zip(calls, contents, strict=True)]
        if stop_after_tools and stop_after_tools([c.name for c in calls]):
            return ""
    resp = await self._respond(model=mdl, instructions=system, input=items)   # text forțat, fără tools
    return resp.output_text.strip()
```

- `_run_tool_calls` și `ToolRun.execute` rămân **neatinse**: execuția, lock-ul, siguranța NX-173 și
  ordinea rezultatelor nu știu pe ce endpoint a venit cererea. `_as_tool_calls` adaptează forma
  (`call_id` → `id`, `arguments` e deja string JSON).
- `_respond` e geamănul lui `_chat`: **aceleași** gărzi, nu copii ale lor. Retry-ul (`_with_retry`),
  bugetul pe apel NX-311 (`call_budget(s, reasoning_on=True)`, deci fereastra de 75 s), `cap_ms`
  NX-241, `prompt_cache_key`, `_note_call`/`record_call`, `_note_truncation`, spanul `model`.
  Cele comune se extrag într-un helper folosit de AMBELE, altfel a doua cale ar diverge tăcut de
  prima la următoarea reparație (exact cum NX-300 a găsit apeluri fără span).
- `usage.request_shape` capătă forma `responses_tools`, iar `record_chat` citește ambele scheme de
  usage. Un apel Responses numărat cu `prompt_tokens=0` ar face costul să pară zero, iar plafonul
  zilnic nu s-ar mai declanșa.
- `_MODEL_PROFILES` capătă un câmp `responses_tools: bool` (azi adevărat doar pentru `gpt-6-luna`,
  `gpt-6-sol`). Flag aprins + model fără capabilitate ⇒ calea de azi + degradare numărată
  `llm_responses_unsupported_model`, nu un 400.

### Felia 1 — măsurarea (fără nicio schimbare pe calea live)

- **P2 (LLM doar în agent):** nu adaugă niciun apel de model, schimbă endpointul celui existent.

## Test Cases

Toate pe fake-uri de client OpenAI (`SimpleNamespace` cu `responses.create` / `chat.completions.create`),
ca `tests/test_llm.py`. **Zero apeluri reale în CI.**

**Happy Path**
1. Flag ON, o rundă cu `search_products` + răspuns text în runda 2 ⇒ `execute` chemat o dată cu
   argumentele parsate, textul întors, `reasoning={"effort":"low"}` pe ambele apeluri.
2. Flag ON, `stop_after_tools` întoarce `True` (profil `recommend`, NX-312) ⇒ bucla iese cu `""` după
   runda 1, fără al doilea apel.
3. Flag OFF ⇒ `chat.completions.create` primește exact kwargs de azi (`reasoning_effort="none"`,
   `tools` în forma cu `function`), iar `responses.create` nu e chemat niciodată.

**Edge Cases**
1. Două `function_call` în aceeași rundă ⇒ rezultatele se întorc în ORDINEA cerută, fiecare cu
   `call_id`-ul lui, chiar dacă execuția a doua termină prima.
2. `max_steps` atins ⇒ ultimul apel pleacă FĂRĂ `tools` (text forțat), ca azi.
3. `_round_admitted()` refuză (NX-241 activ) ⇒ ieșire la apelul final fără tools, fără rundă nouă.
4. Usage fără `input_tokens_details` ⇒ `cached=0`, fără excepție.

**Failure Cases**
1. `responses.create` ridică `BadRequestError` ⇒ nu se reîncearcă (terminal), excepția ajunge la
   `agent_stage`, care cade pe fallback-ul de azi. Nu se încearcă `chat.completions` în locul lui.
2. `status="incomplete"` cu `reason="max_output_tokens"` și `output_text` gol ⇒ degradare
   `llm_responses_incomplete` numărată + text gol întors (fallback determinist în aval).
3. `APITimeoutError` pe runda 1 ⇒ `_with_retry` cu fereastra NX-311 pentru apel care raționează
   (75 s pe încercare, 90 s total), nu 30 s.
