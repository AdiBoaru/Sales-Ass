## De ce contează mai mult decât pare

Principiul 9 din CLAUDE.md spune explicit: *promptul se generează din `categories`, nu hardcodat.*
`prompt_builder.py` chiar face asta pentru categorii — dar exemplele de vocabular au rămas scrise
de mână lângă partea generată. Jumătate din principiu, aplicat.

Consecința la primul vertical nou nu e o eroare, e o **degradare tăcută**: modelul primește exemple
despre ten gras într-un magazin de electrocasnice, le tratează ca pe indicii despre ce se caută
aici, iar calitatea scade fără ca nimic să pice.

Iar `tool_definitions.py` e cel mai subtil: exemplele din descrierea unui parametru sunt
**instrucțiuni pentru model**, nu documentație. Un model care citește „ex. «ten gras»" învață ce fel
de valori se așteaptă acolo.

## Mecanismul

Aceeași regulă peste tot: **textul se compune din pachetul tenantului, la runtime, nu se scrie.**

1. **Exemplele de vocabular** vin din `concern_map` și din valorile fațetelor tenantului, alese
   determinist (primele N după acoperire, ca prefixul de prompt să rămână stabil pentru caching).
2. **Sugestiile de start** se derivă din categoriile cu cea mai mare acoperire + nevoile cu cea mai
   mare acoperire, formulate cu șabloane din pachet, per locale. Un magazin fără pachet primește
   sugestii pe categorii, nu pe nevoi.
3. **Regexurile de obligații** nu enumeră substantive de produs; păstrează doar structura
   (declanșator + referință + cuvinte funcționale ale locale-i), la fel ca `carries_new_constraints`
   din NX-251, care rezolvă deja aceeași problemă corect.

## Capcana de prompt caching

Prefixul static byte-identic e ce dă reducerea de 75-90% la OpenAI (stagiul 6). Un prompt compus
dinamic o pierde dacă ordinea sau selecția variază de la tur la tur.

Deci compunerea trebuie să fie **deterministă și memoizată per (business, locale, versiune de
pachet)**: aceleași intrări ⇒ aceiași octeți. Se verifică prin test, nu prin intenție.

## Principii CLAUDE.md aplicabile

- **P9** — promptul se generează din DB. Cardul închide jumătatea rămasă.
- **P11** — exemplele sunt în limba tenantului, nu în română prin construcție.
- **P13** — textele generate respectă `VOICE_RULES` (fără liniuță de pauză, fără punct și virgulă).

## Implementation Steps

1. `prompt_builder`: exemplele de vocabular din pachet, selecție deterministă, memoizată.
2. `tool_definitions`: descrierile parametrilor compuse din pachet, cu fallback neutru fără exemple.
3. `greeting`: sugestiile derivate din categorii + nevoi, cu șabloane per locale.
4. `triage`: același tratament ca `prompt_builder`.
5. `brain_models`: regexul păstrează structura, scapă de substantive.
6. Șterge intrările corespunzătoare din `tests/domain_leak_baseline.json` — testul cere ca o intrare
   care nu se mai potrivește să fie ștearsă, deci curățenia e forțată, nu opțională.
7. Rulează golden + NX-265: comportamentul nu se degradează.

## Test Cases

**Happy path**
1. Pachet SOLE → exemplele din prompt sunt cuvinte care există în `concern_map`.
2. Două compuneri consecutive → aceiași octeți.

**Edge**
3. Pachet fără `concern_map` → prompt fără exemple, nu prompt cu exemple de beauty.
4. Pachet cu 3 nevoi → 3 exemple, nu N umplute cu ce apucă.
5. Locale diferit → exemplele urmează locale-ul, nu limba codului.

**Failure**
6. Pachet corupt → fallback neutru + contor, niciodată prompt gol.
7. Cineva readaugă un exemplu hardcodat → NX-264 pică, fiindcă intrarea de baseline a fost ștearsă.
