# NX-227 — Concern nemapat: telemetrie + disclosure către model (constrângerea nu se mai pierde tăcut)

**Owner:** Claude (build) / Codex (verify) · **Faza:** Web pilot · **Zi/Ord:** track C, oricând · **Branch:** `feat/NX-227-concern-unmapped` · **Complexitate:** S · **Estimare:** 2h
**Model recomandat:** Opus 4.8

## Goal
`map_concerns` ignoră termenii care nu există în `DomainPack.concern_map`
([taxonomy.py:74-80](../src/tools/taxonomy.py#L74-L80)) — corect ca politică de filtrare
(mai bine zero filtru decât unul greșit), dar pierderea e DUBLU tăcută: (a) nu se emite
niciun eveniment, deci golurile de vocabular din DomainPack nu apar nicăieri — deși pentru
produse există `unmet_query`, iar un termen nemapat e aceeași marfă: cerere pe care n-o
înțelegem; (b) modelul nu află că filtrul a picat, deci poate prezenta rezultatele ca
potrivite „pentru ten reactiv" când filtrul n-a rulat niciodată. Taskul face pierderea
vizibilă în ambele direcții.

## Business Context
Vocabularul DomainPack crește exact din acest semnal: ce cer clienții cu cuvintele lor și
noi nu mapăm. Azi creșterea se face orbește (ghicim sinonime); cu evenimentul, devine
listă prioritizată pe frecvență reală — aceeași logică „cererea neîmplinită e eroul" din
planul de analytics, aplicată la vocabular, nu la produse. Iar disclosure-ul spre model
previne afirmarea falsă de potrivire — onestitate care se vede direct în conversație.

## Technical Description

**1. Split în loc de drop tăcut** (compatibil înapoi — `map_concerns` rămâne):
```python
# src/tools/taxonomy.py
def split_concerns(
    domain_pack: DomainPack | None, raw: list[str] | None
) -> tuple[list[str], list[str]]:
    """(mapate_canonice, nemapate_normalizate). Politica de filtrare NEschimbată:
    necunoscutele nu devin filtru. Dar nu se mai pierd tăcut — apelantul emite + disclose."""
    if not raw:
        return [], []
    table = domain_pack.concern_map if domain_pack else {}
    mapped = sorted({table[_norm(c)] for c in raw if _norm(c) in table})
    unmapped = sorted({_norm(c) for c in raw if _norm(c) and _norm(c) not in table})
    return mapped, unmapped
```
`map_concerns` devine wrapper peste primul element (zero schimbare de comportament pentru
apelanții existenți).

**2. În `search_products_tool`** ([catalog_tools.py:662](../src/tools/catalog_tools.py#L662)):
```python
concern_keys, unmapped = split_concerns(ctx.business.domain_pack, a.concerns)
concern_keys = concern_keys or None
if unmapped:
    ctx.emit("concern_unmapped", terms=unmapped, locale=ctx.language,
             category_key=a.category)
    notes.append(
        f"(nevoile «{', '.join(unmapped)}» nu sunt filtre cunoscute — rezultatele NU sunt "
        f"filtrate pe ele; nu afirma potrivirea pe aceste nevoi, poți întreba o clarificare)"
    )
```
- `terms` = vocabular normalizat (lower, fără diacritice), NU text liber de user — aceeași
  politică P12 ca `variant_attr` din `unmet_query` (atribut scurt, nu propoziție, fără PII).
  Cap de lungime per termen (40, ca `_VARIANT_ATTR_MAX`) + max 5 termeni per event.
- Nota intră în lista `notes` EXISTENTĂ (mecanismul relaxării,
  [catalog_tools.py:934-949](../src/tools/catalog_tools.py#L934-L949)) → zero drum nou spre
  model.
- Semanticul compensează parțial (termenul rămâne în query-ul embedat) — nota o spune
  corect: „nu sunt filtrate", nu „nu s-a ținut cont deloc".

**3. Fingerprint:** cheia `concerns` din `_session_filters` primește DOAR mapatele (ca azi).
Termenii nemapați NU intră în fp — nu afectează retrieval-ul, n-au voie să spargă sesiunea.

**TurnContext:** niciun câmp nou; `notes`/`llm_view` sunt mecanismele existente ale tool-ului.
**Cost:** zero LLM nou.

## Test Cases

2. Tot mapat → drum identic cu main.

**Edge Cases**

   event (dedup pe normalizat).

**Failure Cases**

2. `ctx.emit` care aruncă (stub defect) → NU rupe căutarea (emit e deja best-effort prin
   design-ul TurnContext — verificat cu test).
